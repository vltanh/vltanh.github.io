VieCut

exact cactus mincut with most-balanced tie-break · Henzinger, Noe, Schulz, Strash 2018–2020

The global-minimum-cut engine under WCC and CM. Certified contraction layers wrap a push-relabel max-flow inner loop; the resulting cactus is traversed to read off a most-balanced minimum cut. CC stops before this backend.

Audited draft. This JavaScript trace follows the exact cactus path used by the connectivity post-processors. Its provenance spans the practical-contraction paper (ALENEX 2018), the exact shared-memory algorithm (IPDPS 2019), and the all-mincuts cactus construction (ESA 2020). The evidence card below separates those papers from the deployed adapter.

Take a connected graph \(G = (V, E)\) with non-negative edge weights \(w_e\). A cut is a non-trivial vertex bipartition \((S, V \setminus S)\); its cut-set \(\delta(S)\) is the edges with exactly one endpoint on each side. The global minimum cut is the lightest such cut over every choice of \(S\):

\(\lambda(G) \;=\; \min_{\varnothing \neq S \subsetneq V}\; \sum_{e \in \delta(S)} w_e\).

In plain terms: the cheapest way to break the graph into two pieces. Two properties follow. First, the minimum degree \(\min_v \deg(v)\) is a free upper bound on \(\lambda\), since every vertex sits behind a cut of weight \(\deg(v)\) made of its incident edges. Second, by max-flow-min-cut (Ford-Fulkerson 1956), the global mincut equals the minimum over all \((s, t)\) max-flow values, so one \((s, t)\) probe per recursion frame decides whether a candidate edge can be on any minimum cut.

VieCut's job here is exact global mincut, plus one downstream-friendly tie-break: when several minimum cuts tie, return the split with the largest lighter side. It is a primitive, not a community detector. Tie-breaking and RNG state can affect which equal-value cut is returned, and the label-propagation loop only enters on graphs above the \(|V| > 10{,}000\) threshold.

VieCut is a stack of contraction layers around one max-flow inner loop. The driver runs trivial-cut heuristics, Padberg-Rinaldi tests, heavy-edge contraction, degree-1 cleanup, and capforest contraction until the graph stops shrinking; a recursive build over push-relabel max-flow then produces the cactus, and a DFS over the cactus reads off the most-balanced cut. Each layer covers cases the others miss, and the composition is what separates VieCut's runtime from Stoer-Wagner on real graphs.

Step 1. Start with \(\min_v \deg(v)\) as the running upper bound on \(\lambda\); later LP and contracted-graph degree checks can only lower it. Step 2. Contract only with certificates: PR tests, heavy-edge tests, degree-1 cleanup, and capforest each prove that a pair need not be separated by any minimum cut before unioning it. Step 3. Run push-relabel on one \((s,t)\) probe. A value above \(\lambda\) contracts; a value equal to \(\lambda\) exposes real mincut structure in the residual.

Step 4. Turn residual SCCs into cactus nodes and segments, so tree edges and cycle edge-pairs encode every minimum cut compactly. Step 5. Traverse that cactus and score only cuts of value \(\lambda\); the selected output is the minimum cut with the largest lighter side, which is the split WCC and CM recurse on.

An 8-node unit-weight graph for the active small-graph cactus path.

Two triangles \(\{0, 1, 2\}\) and \(\{3, 4, 5\}\) joined by the bridge \((2, 3)\), plus pendants \(6\) on vertex \(2\) and \(7\) on vertex \(3\), plus two cross-edges \((0, 4)\) and \((1, 5)\) so the push-relabel probe inside the cactus build has non-trivial work. Eleven undirected edges, all of unit weight; the mutable graph stores those as 22 directed arcs. The free upper bound \(\min_v \deg(v) = 1\) gives the starting estimate \(\lambda_0 = 1\).

8 nodes · 11 undirected edges · unit weights \(\lambda_0 = 1\) from min-degree

The two pendant edges achieve \(\lambda = 1\): isolating \(6\) cuts only \((2, 6)\), and isolating \(7\) cuts only \((3, 7)\). The bridge \((2, 3)\) is not a one-edge minimum cut in this fixture, because separating the two triangles also crosses \((0, 4)\) and \((1, 5)\), for total cut value 3. Their weight sum is 3, so \(w(\delta(S)) = 3\). This is a valid cut but not a minimum one; \(\lambda = 1\) is achieved by either pendant cut.

Step 1. Choose the side \(S\); a cut is a vertex partition, not just an edge you would like to delete. Step 2. List every crossing edge. The bridge split pays not only for \((2,3)\), but also for \((0,4)\) and \((1,5)\), because all three have one endpoint on each side. Step 3. Add the weights. Unit weights make the value a count on this fixture, and the selector may compare balance only after the value equals \(\lambda\).

Two properties follow. First, \(\lambda(G)\) is determined by \(G\) alone but the minimum-cut bipartition is rarely unique; this fixture has two pendant minimum cuts. Second, max-flow-min-cut implies that probing \((s, t) = (0, 5)\) and computing the max-flow gives the minimum \((0, 5)\)-cut weight, which on this fixture is 3, since 0 and 5 sit on opposite sides of the cut shown above. The global \(\lambda = 1\) is a lower bound over all \((s, t)\) choices.

stage 2 · Stoer-Wagner baseline

The classical baseline.

Before VieCut, the standard textbook approach was Stoer and Wagner 1997. One phase runs a maximum-adjacency ordering: pick a starting vertex, then repeatedly append to the order the vertex with the largest summed weight of edges back into the already-ordered set. The second-to-last and last vertices added define an \((s, t)\) pair; the cut isolating the last vertex from the rest is a minimum \((s, t)\)-cut. Contract \(s\) and \(t\), recurse, keep the lightest phase-cut across \(|V| - 1\) phases. That is \(\lambda(G)\).

\(O\bigl(|V| \cdot |E| + |V|^2 \log |V|\bigr)\) running time

In plain terms: every phase scans every edge once and maintains a max-adjacency priority queue, and there are \(|V| - 1\) phases. Two properties: it never invokes max-flow, so constants are small; the \(|V| \cdot |E|\) factor dominates on dense graphs, and the algorithm returns one minimum cut, not the whole family.

one Stoer-Wagner phase from start vertex 0 order shown by yellow rank labels

VieCut differs from Stoer-Wagner in three places. It contracts before invoking max-flow (NOI capforest, Padberg-Rinaldi, degree-1, heavy edges), so the graph going into max-flow is much smaller than \(|V|\). It uses Goldberg-Tarjan push-relabel per \((s, t)\) probe inside Karzanov's cactus construction, where each probe is cheap because the graph has already been contracted. It returns the cactus, which encodes every minimum cut at once, so a downstream selector can pick the most-balanced one instead of receiving an arbitrary single cut. On a cluster of 5,000 nodes, Stoer-Wagner runs the maximum-adjacency ordering 4,999 times; VieCut's outer loop typically converges in 3 to 5 passes.

stage 3 · trivial cuts via label-propagation

Cheap cluster hypotheses tighten the \(\lambda\) upper bound.

On graphs with \(|V| > 10{,}000\), the driver first runs a fast clustering pass to find candidate cuts before the cactus pipeline starts. The pass is label-propagation: initialise every node with its own label, then for two iterations walk the nodes in a chunk-shuffled order, summing incoming edge weight per neighbour-label and picking the heaviest. The contracted graph at the end of the pass has \(k\) super-nodes (one per cluster); its minimum degree is an upper bound on \(\lambda\).

\(\lambda \;\le\; \min_{v \in V'} \deg_{G'}(v)\)

where \(G'\) is the contracted graph. In words: any cut that isolates one super-node in \(G'\) lifts to a cut in \(G\) of the same weight, so the minimum degree on the smaller graph is a free new upper bound. Two properties: the bound is monotone, so the LP pass cannot make \(\lambda\) larger; and the bound only helps when LP finds visible cluster structure, since a clustering that gives back the input graph wastes work.

illustration: if LP partitioned the fixture into the two visible triangles contracted super-graph would have 2 super-nodes, 3 cut edges, \(\min \deg = 3\)

LP also feeds a small-block trimming pass: any cluster smaller than \(\log_2 |V|\) is peeled if peeling brings its block-degree below the running \(\lambda\). After LP, Padberg-Rinaldi runs on the contracted super-graph for one more round of tightening. On the 8-node fixture the LP path is skipped (the threshold is \(|V| > 10{,}000\)); the contracted-graph view above is what LP would emit at scale.

the one floating-point primitive on the entire pipeline

The trim threshold \(\log_2 |V|\) is the only floating-point operation in VieCut. V8 ships the same fdlibm-derived logarithm as libstdc++, and on integer-valued \(|V|\) both produce identical bit patterns. This is what makes the byte-equal port possible; a different math library on the JS side would have surfaced ulp-level disagreement here. Stress testing confirms agreement at every input size sampled.

stage 4 · Padberg-Rinaldi PR1

One edge, one local test, one contraction.

The simplest Padberg-Rinaldi certificate (1990) reads: if \(w(u, v) \ge \lambda\) and \(u\) has weighted degree summing to at least \(2\lambda\) on edges other than \((u, v)\), then every cut separating \(u\) from \(v\) costs at least \(2\lambda > \lambda\), so no minimum cut has them on opposite sides. Union \(u\) and \(v\). On the fixture with \(\lambda = 1\), every edge passes the threshold, and one of the first edges PR1 fires on sits between two triangle vertices like \(0\) and \(1\), where the surrounding triangle adds two more incident edges of weight 1 each.

\(w(u, v) \ge \lambda \quad \text{and} \quad \sum_{e \in \delta(u) \setminus \{(u, v)\}} w_e \ge 2\lambda \;\Longrightarrow\; \text{contract } (u, v).\)

In plain terms: a heavy edge in a heavy local neighbourhood cannot survive any minimum cut, because cutting it would force the cut to cross at least two more incident edges of comparable weight. Two properties: the test is purely local (one edge plus one vertex degree), so it runs in time proportional to the edges it inspects; and PR1 composes monotonically with the running \(\lambda\) estimate, since tightening \(\lambda\) only adds new triggering edges.

PR1 fires on edge \((0, 1)\): \(w = 1 \ge \lambda\), \(\deg(0) \setminus (0, 1) = 3 \ge 2\lambda\) green = contraction

The proof is a standard exchange argument. Suppose some minimum cut \(C\) separates \(u\) and \(v\). Then \(C\) contains \((u, v)\) plus at least one edge from \(\delta(u) \setminus \{(u, v)\}\) (otherwise \(u\) sits behind a one-edge cut of weight \(w(u, v)\) that uses no other edge, contradicting that \(C\) splits \(u, v\)). The weight of \(C\) is then at least \(w(u, v) + 2\lambda - w(u, v) = 2\lambda > \lambda\), contradicting that \(C\) was minimum.

stage 5 · Padberg-Rinaldi PR2, PR3, PR4

Multi-edge tests catch what PR1 misses.

PR1 looks at one edge plus one vertex degree. PR2 sharpens by considering common neighbours: if \(u\) and \(v\) share a common neighbour \(w\) with \(w(u, w) + w(v, w) \ge \lambda\), the triangle \(\{u, v, w\}\) carries enough weight that any cut splitting \(u\) from \(v\) must cross at least \(\lambda\) inside the triangle. PR3 widens to two-hop chains; PR4 looks at edge-pairs sharing only one endpoint. All four tests share the same exchange-argument template.

\(\exists \text{ common neighbour } w:\; w(u, w) + w(v, w) \;\ge\; \lambda \;\Longrightarrow\; \text{contract } (u, v).\)

In plain terms: if two vertices share a neighbour with enough combined weight to themselves carry a \(\lambda\)-cut, the two vertices can be merged. Two properties: PR2 is the first test that triangulates over neighbours, so it finds contractions PR1 misses on sparse high-degree configurations; and the four tests together typically contract another 5 to 20% of the vertices per outer pass on real graphs.

PR2 fires on edge \((4, 5)\) via common neighbour 3: \(w(4, 3) + w(5, 3) = 2 \ge \lambda = 1\) green = contraction

The pipeline runs PR1 and PR2 first as a pair, then a contraction, then PR3 and PR4, then another contraction. The order is not interchangeable: PR3's two-hop tests benefit from PR12 having already contracted the obvious edges, because contracting an edge merges two neighbourhoods and lets a PR3 certificate fire on the merged structure. On the fixture, PR12 unions \((0, 1)\) and \((4, 5)\) via the triangles, then PR34 picks up further reductions in the surrounding bridge structure.

stage 6 · heavy-edge contraction

Edges of weight strictly greater than \(\lambda\) cannot survive any minimum cut.

Before the recursive cactus build runs, a sweep over the input graph contracts every edge whose weight strictly exceeds the running \(\lambda\). The certificate is one line: any cut crossing an edge of weight \(w > \lambda\) has weight at least \(w > \lambda\), so the edge cannot be on any minimum cut.

\(w(u, v) \;>\; \lambda \;\Longrightarrow\; \text{contract } (u, v).\)

In plain terms: heavy edges are the cheapest possible certificate. Two properties: the test is local and runs in linear time over the edges; and it composes with all four PR tests, since any PR-eligible heavy edge also contracts here. On unit-weight graphs the heavy-edge layer fires zero times until contractions create super-edges of accumulated weight, at which point it cleans up the inside of contracted blocks.

on the fixture: \(\lambda = 1\), all edges have weight 1, so heavy-edge fires zero times at level 0 illustration: a level-1 super-edge of weight 3

The sweep also picks up degree-2 vertices whose two incident edges both weigh exactly \(\lambda\). Such a vertex sits on a degenerate cycle that the cactus would represent as one tree edge anyway, so the pre-contraction folds it into one of its neighbours. The two pre-contractions (heavy edge, degree-2 cycle) are reversed at the end of the recursive build so the output cactus references original vertices.

stage 7 · degree-1 cleanup

Pendants whose only edge weighs \(\lambda\) are free contractions.

After each contraction phase, a one-pass sweep over the vertices looks for degree-1 super-nodes whose single incident edge weighs exactly \(\lambda\). Each such super-node sits behind a cut of weight \(\lambda\) on its own: cutting its one edge isolates it. The cut is already a minimum cut, so the edge is on at least one minimum cut, so its endpoints can be unioned. The pendant and its neighbour share the same side of the most-balanced cut and become one cactus node.

\(\deg(v) = 1 \;\text{ and }\; w(\text{only edge of } v) = \lambda \;\Longrightarrow\; \text{contract } v.\)

In plain terms: a leaf hanging off the graph by a single edge of the cheapest weight is the cheapest possible cut. Contracting it loses no minimum cut, since the leaf belongs to one of them already. Two properties: the test runs in linear time over the vertex set; and it never tightens \(\lambda\), since pendant cuts realise the bound exactly.

pendants 6 and 7 both have degree 1, weight 1, \(\lambda = 1\); both contract green = unioned with neighbour

On real inputs the phase often does no work after the first outer pass: by then most degree-1 super-nodes have been absorbed by their neighbours through the capforest union triggers (stage 8 below). The phase stays in the pipeline to cover degenerate input shapes where capforest skips the union, typically when the starting vertex sits on the far side of the graph from the pendant.

Contraction invariant. Every contraction layer emits a union-find, not an edited graph. The shared rebuild step maps each component to one super-node, drops self-loops, sums parallel crossing edges, and keeps enough reverse mapping to lift cactus nodes back to original vertices. That is why PR, degree-1 cleanup, heavy-edge contraction, and capforest can be reasoned about independently.
stage 8 · capforest contraction

One PQ pop per step, accumulate per-vertex residual mass, union when it crosses \(\lambda\).

Capforest is VieCut's main contraction layer (Nagamochi-Ono-Ibaraki 1992). Structurally it is a Stoer-Wagner maximum-adjacency traversal, but the per-vertex accumulator is capped at \(\lambda\). The cap is what makes the bucket priority queue work: \(\lambda + 1\) buckets suffice instead of \(O(|V|)\). Pick a random starting vertex (one RNG draw, modulus \(|V|\)), insert it with key 0, then loop. Each iteration pops the highest-key vertex \(u\), and for each unvisited neighbour \(t\) with edge weight \(w\) tests:

\(r_v[t] + w \;\ge\; \lambda \;\Longrightarrow\; \text{union } (u, t).\)

Then update \(r_v[t] \mathrel{+}= w\) and either insert \(t\) into the queue or raise its key to \(\min(r_v[t], \lambda)\). The accumulator \(r_v\) is integer everywhere (edge weights are integer in VieCut), so there is no floating-point drift.

Step 1. Draw one start vertex, set every residual accumulator \(r_v[\cdot]\) to 0, and insert the start with key 0. Step 2. Pop the unvisited vertex with the largest capped key, matching maximum-adjacency traversal. Step 3. Before raising a neighbour's key, test \(r_v[t] + w \ge \lambda\); if true, union the endpoints immediately. Step 4. After the pass, contract each union-find component into one super-node and sum parallel crossing edges.

In plain terms: by the time \(u\) and \(t\) are both visited, the accumulator on \(t\) has been pushed across the running mincut estimate by this one edge, which proves they share the same side of some minimum cut. Two properties: the comparison is non-strict, so exact-equal triggers the union (this is the byte-equal-replay-critical site); and the test fires only when \(r_v[t]\) was still strictly below \(\lambda\) before the edge weight was added, so each pair unions at most once across the whole pass.

The correctness proof is the same exchange argument as the Padberg-Rinaldi family. If some minimum cut separates two vertices that capforest unioned, swap one of them to the other side; the cut weight strictly decreases, contradicting minimality. The union-find at the end of the pass partitions \(V\) into super-nodes guaranteed to share a side of some minimum cut. Contracting them shrinks the graph without losing any minimum cut.

why max-adjacency ordering

Capforest is structurally Stoer-Wagner's maximum-adjacency ordering with one twist: the priority queue key is capped at \(\lambda\) so it fits in a bucket of size at most \(\lambda + 1\). This swaps the \(\log |V|\) cost of a binary heap for constant cost per operation when \(\lambda\) is moderate. On every benchmark graph in this gallery the per-cluster mincut stays small (typically under 50), so the bucket queue is the fast path. Inside one bucket the realised variant is first-in-first-out, which matters for byte-equal replay: two vertices that share the same residual mass pop in insertion order, not in vertex-ID order.

stage 9 · push-relabel max-flow

One push or relabel per step; gap heuristic + global relabeling for speed.

Once the contraction layers stop shrinking the graph, the recursive build calls Goldberg-Tarjan push-relabel (1988) per recursion frame. Each \((s, t)\) probe seeds the graph with preflow \(\infty\) leaving the source, then iteratively discharges active vertices by pushing excess flow forward and raising vertex distances when no forward push is possible. The algorithm terminates when no vertex has positive excess; the resulting flow value is the max-flow.

\(\text{push } (u, v): \quad d(u) \;>\; d(v).\)

In plain terms: flow moves only to strictly-lower distance labels, never sideways. Two properties: this rule keeps the distance labels admissible (they form a valid lower bound on residual shortest-path distance), which proves correctness; and the implementation comparator is non-strict \(\le\) reading "block if not strictly higher", so equal-distance pushes are blocked. This is one of the byte-equal-replay-critical sites.

Step 1. The cactus recursion chooses a high-degree source and a heaviest adjacent target so the first probe is likely to contract useful mass. Step 2. Push-relabel returns the exact value of the lightest cut separating this particular \(s\) from \(t\). Step 3. Compare that value with \(\lambda\): if it is larger, no global minimum cut separates \(s\) and \(t\), so the pair can be contracted. Step 4. If the value equals \(\lambda\), the residual graph is already the certificate used to build the next cactus segment.

push-relabel snapshot: probe \((s, t) = (0, 5)\); blue arc carries flow distance labels: \(d(0) = 4, d(2) = 3, d(3) = 2, d(5) = 0\)

The recursive build branches on the resulting flow value: if max-flow strictly exceeds \(\lambda\) the \((s, t)\) edge is on no minimum cut, so contract it and recurse; if max-flow equals \(\lambda\) a cut of value \(\lambda\) exists in the residual graph, so run strongly-connected-components on the residual and assemble the cactus from the SCC quotient. The two heuristics push-relabel relies on for performance are the gap heuristic (if some distance label has zero count, every vertex above it is disconnected from the sink and can be relabeled in bulk) and global relabeling (every few thousand work units, a full reverse-BFS from the sink resets distances to true residual distances).

stage 10 · cactus structure

Karzanov's tree-with-cycles encodes every minimum cut.

Karzanov 1973 proved: in any undirected graph \(G\) with global minimum cut value \(\lambda\), all minimum cuts can be encoded by a cactus tree-with-cycles \(T\) such that each node of \(T\) holds a contracted set of original vertices, each tree edge of \(T\) corresponds to a cut of weight \(\lambda\), and each cycle of \(T\) holds a family of cuts of weight \(\lambda\) obtained by cutting any two cycle edges.

\(|T| \;\le\; |V|, \qquad \#\{\text{distinct minimum cuts}\} \;\le\; \binom{|V|}{2}.\)

In plain terms: instead of enumerating exponentially many subsets, the cactus compresses every minimum cut into a tree-with-cycles of size at most \(|V|\). Two properties: tree edges in the cactus correspond to "isolated" minimum cuts that cannot be obtained from another by exchanging two cycle edges; cactus cycles correspond to equivalence classes of minimum cuts that share the same two cactus partition shapes.

A cactus node stores the original vertices that contraction proved inseparable for minimum-cut purposes. Delete one cactus tree edge and the vertices reachable on either side lift to a minimum cut of value \(\lambda\). On a cactus cycle, deleting two cycle edges chooses one contiguous block and its complement, with the two edge weights summing to \(\lambda\). If a vertex subset is not represented by one tree edge or one cycle pair, it is not a global minimum cut.

example: \(C_4\) (four vertices, four unit edges) has \(\lambda = 2\) and six minimum cuts cactus: a single 4-cycle, each cactus edge weight 1

The minimum cuts of \(C_4\) come from choosing any two cactus-cycle edges. Adjacent edge pairs isolate one original vertex; opposite edge pairs split the cycle into two adjacent pairs. There are \(\binom{4}{2} = 6\) such edge pairs, and the cactus encodes all six without listing six vertex subsets. The two-edge-cut weight rule \(\lambda / 2\) per cactus cycle edge ensures every chosen pair sums to \(\lambda\).

A useful intuition: the cactus is to minimum cuts what the Gomory-Hu tree is to all-pairs max-flow. The Gomory-Hu tree compresses \(|V| (|V| - 1) / 2\) max-flow values into a tree on \(|V|\) nodes. The cactus compresses every minimum-weight cut into a tree-with-cycles on at most \(|V|\) nodes. Both rely on the same algebraic structure: cuts behave like a sub-modular lattice, and the lattice of minimum-value elements has a tree representation.

stage 11 · recursive cactus refinement

Pick an \((s, t)\) pair, run max-flow, branch on whether the flow exceeds \(\lambda\).

The recursive build receives the contracted graph stack from the outer loop and a depth counter. At each frame: pick \(s\) as the vertex with the largest total incident weight, then pick \(t\) as the neighbour of \(s\) connected by the heaviest single edge (no RNG draw at this site, ties resolved by ascending vertex-id iteration). Run push-relabel max-flow. Branch on the result.

\(\text{max-flow} \;>\; \lambda \;\Rightarrow\; \text{contract } (s, t) \text{ and recurse}; \quad \text{max-flow} = \lambda \;\Rightarrow\; \text{SCC and findSTCactus}.\)

In plain terms: when the flow exceeds \(\lambda\) the candidate edge cannot lie on any minimum cut, so contract it and shrink the problem; when the flow equals \(\lambda\) the residual carries a minimum cut, so decompose into strongly-connected components and segment the SCC quotient. Two properties: the contract-branch always strictly shrinks the graph, so recursion depth is bounded by \(|V|\); and the SCC-branch produces the actual cactus growth, with one new cactus segment per frame entered through it.

Step 1. After max-flow \(=\lambda\), residual strongly-connected components are the indivisible pieces for this \((s,t)\)-cut. Step 2. Contract each SCC to a slot and keep the residual cut weights between slots. Step 3. Scan slot order with a bucket queue while a cycle-degree accumulator decides whether the current segment stays open. Step 4. Attach the closed segment: saturated segments become cactus cycles; fully drained segments become tree edges with weight \(\lambda\).

findSTCactus: PQ-pop ordering of SCC quotient, segmented into A-cycles + B-tree-segments orange cycle = A-segment; green tree edge = B-segment

The cycle-tree split inside findSTCactus is driven by a cycle-degree accumulator. At each slot, the running sum of weights crossing into already-popped slots is checked: when it equals 0 or equals \(\lambda\) on a slot boundary, the current segment closes and a new one starts; otherwise the slot extends the current segment.

cycle_degree \(== 0\) or cycle_degree \(== \lambda\) \(\Rightarrow\) close segment.

In plain terms: a slot continues the current segment if its accumulated cross-weight is either fully drained or fully saturated; anything in between closes it. Two properties: this is a double-equality predicate, so exact-equal at \(\lambda\) is the active branch (off-by-one breaks the cactus); and the test fires per slot, so the cycle-tree pattern is decided greedily in one pass without backtracking.

stage 12 · sliding-window most-balanced cut

DFS the cactus; score \(\min(|S|, |V \setminus S|)\); slide a window across cycles.

The most-balanced selector traverses the cactus by DFS. For each tree edge: compute the lighter side's node count after removing the edge from the tree; this gives a candidate balance score \(\min(|S_e|, |V \setminus S_e|)\). For each cycle: slide a window over the cycle vertex sequence; at each window position the two endpoints define a candidate two-edge cut. The selector maximises the score over every minimum cut and lifts the winning bipartition back to original vertices by reading the contained-vertex tables on each cactus node.

\(\text{argmax over cuts of weight } \lambda:\; \min(|S|, |V \setminus S|).\)

In plain terms: among all minimum cuts, pick the one whose two sides come closest to equal in node count. Two properties: the score is intentionally simple, since the cactus naturally exposes the contained-vertex tables on each node; and the comparators differ between tree edges (strict \(>\), first improvement wins) and cycle windows (non-strict \(\ge\), later equal-score positions override earlier), which biases toward the cycle's median position.

Step 1. Count payload sizes: each cactus node has a contained-vertex list, and subtree sizes sum those payload lengths. Step 2. Test only mincut edges. A tree edge is a candidate only when its cactus edge weight equals \(\lambda\); cycle candidates are pairs whose total is \(\lambda\). Step 3. Score the lighter side, because balance is the objective once cut weight has already been fixed. Step 4. Recover original vertices by running a final BFS over the cactus, blocked at the chosen cut edge or edge pair, and expanding payloads back to original ids.

stage 13 · LP-loop convergence on \(|V| > 10{,}000\)

Label-propagation + Padberg-Rinaldi tighten \(\lambda\) before the cactus pipeline.

For graphs with more than \(10{,}000\) nodes, the driver runs the trivial-cuts label-propagation pass from stage 3 as the outer loop entrance. After two LP iterations the graph is re-indexed by encounter order, a small-block trimming pass peels blocks below \(\log_2 |V|\), the contracted super-graph passes through PR12 and PR34, and the loop continues while the super-graph still has more than \(10{,}000\) nodes and the previous iteration actually shrank it.

\(\lambda_{k+1} \;=\; \min\bigl(\lambda_k,\; \min_{v \in V'_{k+1}} \deg_{G'_{k+1}}(v)\bigr).\)

In plain terms: every LP iteration replaces the running \(\lambda\) estimate with the smaller of (the previous estimate, the contracted graph's minimum degree). Two properties: the sequence is monotone non-increasing, so the loop cannot revert; and the loop exit is conservative on shrinkage, since an iteration that produces a graph identical in size to the previous one exits even if \(\lambda\) tightened.

an RNG-stream subtlety

The LP body does not draw RNG when one neighbour-label strictly beats the rest; the draw only fires on equal-weight ties. This is a deliberate short-circuit in the canonical source and was the most delicate part of matching the byte-equal port. On graphs with many strict winners the RNG stream stays untouched for long stretches; on graphs with many ties (binary edge weights, roughly balanced communities) the stream advances rapidly. The walker on this page runs at \(|V| = 8\) and never enters the LP-loop path; the kernel exposes it for the \(|V| > 10{,}000\) fixtures the verification harness runs against.

stage 15 · used by WCC and CM; bypassed by CC

Only positive-threshold repair reaches the mincut backend.

VieCut is a primitive, not a clustering algorithm itself. It is the mincut backend other post-processors call when they need an exact global minimum cut on a cluster.

Step 1. WCC or CM induces the current cluster graph. Step 2. VieCut returns exact \(\lambda\), the cluster's edge connectivity, not a modularity or density score. Step 3. The caller compares \(\lambda\) to its positive well-connectedness threshold. Step 4. When the cluster fails, the most-balanced VieCut bipartition becomes repair material. CC takes the ConnectednessCriterion::Simple branch immediately after connected components and never constructs MinCutCustom.

caller question asked of VieCut how the output is used
WCC Is this cluster's mincut at least \(f(n)=\log_{10} n\)? If not, split along the most-balanced mincut and recurse.
CM Does the current reclustered piece pass the same well-connectedness predicate? If not, split, then run the base algorithm again inside each half before re-checking.
CC No VieCut query. The binary emits the already-computed connected components directly.
  • WCC (well-connected check) calls VieCut on every cluster to check whether the cluster's intra-edge mincut clears a connectivity threshold \(f(n) = \log_{10} n\); clusters that fail get split along the most-balanced cut and re-checked recursively. The cactus exposes which cut WCC uses; when the minimum-cut family contains a balanced option, the selector keeps WCC's recursion from stripping a single node per round.
  • CM (Connectivity Modifier) does the same well-connectedness check, and additionally re-clusters each half with the base algorithm (Leiden or Louvain) before re-checking, which lets a deeper recursion expose smaller well-connected pieces. The mincut RNG state carries across rounds; the base algorithm's RNG is re-seeded per round.
  • CC shares the MincutOnly executable but not its mincut loop. Criterion 0 selects the simple branch, so connected components are the final output and VieCut draws no RNG.

WCC and CM verification exercises the VieCut port; CC verification exercises only the deterministic connected-components branch. For the mincut routes, the trace claim is JS port equals the ordered tracer build. Raw trajectory identity with every unmodified C++ build is narrower because unordered-container iteration can change equal-cut paths.

why a separate primitive rather than inlining

Park 2024 and Vu-Le 2026 designed CM and WCC as algorithm-agnostic post-processors. Both define a well-connectedness predicate that depends only on the cluster's induced subgraph and a connectivity threshold. The mincut subroutine sits behind that predicate; swapping VieCut for Stoer-Wagner (or a Gomory-Hu tree) would change wall-clock but not output. The cactus build is the only piece of the chain that materialises every minimum cut at once, which is what the most-balanced selector needs to make a structurally sensible split.

where the LP-loop path matters

On the gallery's empirical inputs the per-cluster mincut queries stay strictly under \(|V| = 10{,}000\), so the LP-loop branch of stage 13 only fires on the whole-graph queries with more than \(10{,}000\) nodes. The gallery runs three such inputs. The per-cluster queries from WCC and CM stay strictly under the threshold, so the bulk of work is the cactus build on already-small graphs, where push-relabel runs on a graph that the contraction layers have substantially pruned.
