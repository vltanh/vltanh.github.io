VieCut

cactus mincut with most-balanced tie-break · Henzinger, Noe, Schulz, Strash 2018

The global-minimum-cut engine sitting under WCC and CM. Builds the cactus tree that encodes every minimum cut, then picks the cut that splits the graph most evenly.

Draft. First-pass walker over a JavaScript port of VieCut (Henzinger et al. 2018, ALENEX). The kernel under this page owns the seven phases of cactus_mincut and is shared with the WCC and CM pages as their mincut backend. Implementation detail and source-code pointers live in the technical reference.

Take a connected graph. The minimum cut is the smallest set of edges you can remove to disconnect it. Write \(\delta(S)\) for the set of edges with exactly one endpoint in \(S \subset V\). The minimum cut value is

\(\lambda(G) = \min_{\varnothing \neq S \subsetneq V}\; \sum_{e \in \delta(S)} w_e\).

The cardinality of any minimising \(\delta(S)\) (when edge weights are unit) is the graph's edge connectivity. Any question of the form "is this cluster well-connected enough to keep as one piece" reduces to a minimum-cut query, which is why WCC and CM call mincut on every cluster they inspect.

Two things make the global-mincut problem harder than it looks. First, \(2^{|V|-1}\) subsets to consider in the naive picture. Second, the minimum cut is often not unique: any pendant node sits behind a cut of size 1, but so does a genuine community boundary, and choosing among them changes what the surrounding algorithm sees next.

VieCut handles both. It builds the cactus tree (Karzanov 1973), a compact data structure whose tree edges and tree cycles enumerate every minimum cut of the original graph, then runs a DFS over the cactus to pick the cut whose two sides come closest to equal in node count.

Why the cactus.

Karzanov's 1973 result: in any undirected graph \(G\) with global minimum cut value \(\lambda\), all minimum cuts can be encoded by a cactus tree-with-cycles \(T\) such that

  • each node of \(T\) holds a contracted set of original-graph vertices;
  • each tree edge of \(T\) corresponds to a cut of weight exactly \(\lambda\); cutting that edge splits \(T\) into two pieces, and the union of original vertices on each side gives a minimum cut of \(G\);
  • each cycle of \(T\) holds a family of cuts of weight \(\lambda\) obtained by cutting any two cycle edges; the original-vertex sides are read off the two cycle pieces.

So instead of enumerating exponentially many subsets of \(V\), VieCut builds one cactus and reads every minimum cut off it. The cactus has at most \(O(|V|)\) nodes, and any minimum cut on \(G\) corresponds to either one tree-edge cut or one two-cycle-edge cut on the cactus.

Why most-balanced tie-break.

Picture a cluster shaped like two dense halves joined by a single bridge edge, plus one pendant node hanging off the side. The minimum cut value is 1, and at least two distinct cuts achieve it:

  • balanced: cut the bridge; the two halves end up on opposite sides.
  • pendant: cut the pendant edge; one node ends up isolated, the rest stays together.

Both are minimum cuts. The pendant choice peels one node and leaves the structural problem untouched; the balanced choice exposes the actual structure. Algorithms like WCC and CM recurse on the resulting halves, so the choice of which minimum cut to return shapes the entire downstream recursion.

VieCut walks the cactus and picks the cut whose lighter side has the most nodes. If two cuts tie on balance, the first one encountered in DFS order wins. This is the most-balanced minimum cut; it gives WCC and CM a partition that exposes the structural boundary instead of stripping one node per round.

stage 2 · the outer loop

Contract until the graph stops shrinking.

The top-level driver runs an outer while-loop. Each pass through the body applies four contraction phases (NOI capforest, degree-1 cleanup, Padberg-Rinaldi tests 1+2, Padberg-Rinaldi tests 3+4) in sequence. After each phase, edges identified as definitely-kept (their endpoints are guaranteed to share the cut side) get merged via union-find, and the graph is rebuilt at the new coarser granularity.

The loop guard is a 1% shrinkage test: keep going while n_after < 0.99 ċ n_before. Once the four phases together fail to shrink the graph by at least 1%, the outer loop exits and control passes to Phase E (recursive cactus build).

This is a fixed-point pattern. Every phase either tightens the running mincut estimate or guarantees an edge contraction; nothing is ever undone. The running estimate starts at the minimum node degree of the graph (a trivial upper bound on \(\lambda\)) and tightens as contractions surface lower-degree super-nodes.

why four contraction phases

Phase A (NOI capforest, Nagamochi-Ono-Ibaraki 1992) is a priority-queue traversal that accumulates a per-vertex residual mass and unions endpoints when the running residual hits the mincut estimate. Phase B is a one-liner: any node with degree exactly \(\lambda\) and one incident edge of weight \(\lambda\) is the endpoint of a trivial cut, so the edge is merged. Phases C1+C2 (Padberg-Rinaldi tests, Padberg + Rinaldi 1990) are local edge criteria of the form "this edge is on some minimum cut" or "this edge is heavier than \(\lambda\) so it cannot be on any minimum cut"; both directions lead to contractions. Each phase has different strengths on different graph shapes, which is why they run in sequence rather than picking one.

stage 3 · capforest contraction

One pop per step, accumulate per-vertex residual mass.

Phase A is the workhorse. Pick a random starting vertex (one RNG draw, next() % n), insert it into a bucket-bounded max priority queue with key zero, then loop:

  • pop the highest-key vertex \(u\); mark it visited;
  • for each unvisited neighbour \(t\) of \(u\): if the running residual \(r_v[t]\) is still below the current mincut estimate, check whether adding the incident edge weight \(w\) would push it to or above \(\lambda\); if so, union \(u\) and \(t\) (they are now guaranteed to share a side in some minimum cut);
  • update \(r_v[t] \mathrel{+}= w\) and either insert \(t\) into the queue or raise its key to \(\min(r_v[t], \lambda)\).

The accumulator \(r_v\) is integer everywhere (edge weights are integer in VieCut), so there is no floating-point drift to worry about. Tie-break is by adjacency-iteration order, which is stable because the underlying mutable graph stores neighbours in insertion order.

Why this works: the union-find at the end of the pass partitions \(V\) into super-nodes such that all edges within a super-node are guaranteed to be on the same side of some minimum cut. Contracting those super-nodes shrinks the graph without losing any minimum cut.

stage 4 · the recursive cactus build

Pick a vertex pair, run max-flow, branch on whether the flow exceeds \(\lambda\).

Once the outer loop has contracted as much as it can, Phase E builds the cactus itself. The driver picks two vertices \(s, t\) using the heaviest-weighted-flow-edge selector (no RNG draw; deterministic over the contracted graph), runs Goldberg-Tarjan push-relabel max-flow between them, and branches on the resulting flow value:

  • if max_flow > \(\lambda\): the \((s, t)\) edge is on no minimum cut, so contract it and recurse on the smaller graph;
  • if max_flow = \(\lambda\): the cut exists in the current residual graph, so run strongly-connected-components on the residual; the SCC quotient gives the cactus structure;
  • if \(n = 2\): single-edge base case; return the two-node cactus.

The SCC-and-merge step is where the cactus takes its actual shape. Each SCC becomes one cactus node holding the originally-contracted vertices; an inner routine called findSTCactus walks a priority-queue ordering of the SCC quotient and segments it into A-cycles (corresponding to families of equivalent minimum cuts crossing a cycle pair) and B-tree-segments (single-edge minimum cuts).

a small subtlety: the singleton-cut variant

Three conditions can co-occur after a max-flow call: max_flow equals \(\lambda\), the SCC decomposition yields exactly two components, and at least one of \(s, t\) already has weighted degree exactly \(\lambda\). When all three hold, one endpoint is already a "minimum-degree witness" for its own cut, and the cactus build takes a special branch that contracts \((s, t)\), recurses, and then attaches a fresh cactus node holding the contracted-side originals with a tree edge of weight \(\lambda\). This preserves the singleton cut as an explicit tree edge in the output instead of folding it into the recursion.

stage 5 · most-balanced bipartition

DFS the cactus to pick the most-even cut.

Once the cactus is built, every tree edge and every cycle-pair represents a minimum cut. The most-balanced selector enumerates those by depth-first search:

  • start at a random cactus node (one RNG draw, nextInt(0, |T| - 1));
  • for each tree edge \(e\) of weight \(\lambda\): compute the lighter side's node count after removing \(e\) from the tree; this gives a candidate balance score;
  • for each cycle: slide a window over the cycle vertex sequence; at each window position the two endpoints define a candidate two-edge cut; compute the lighter side's node count;
  • keep the running maximum lighter-side node count.

The tie-break inside the cycle walk is non-strict (>= instead of >): when two window positions tie on balance, the later one wins. The tree-edge tie-break is strict (>): the first encountered wins. These are read directly off the canonical source and matter for byte-equal verification, but on most fixtures the result is the same partition either way.

The chosen cut translates back into the original graph by reading the containedVertices tables on each cactus node: the lighter-side cactus nodes hold one set of original vertices, the heavier-side cactus nodes hold the other.

stage 6 · the LP-loop heuristic for \(n > 10000\)

On large graphs, a label-propagation pass tightens the mincut estimate first.

For graphs with more than \(10000\) nodes, the cactus pipeline above is too slow to apply directly. VieCut adds a fast outer heuristic that runs before the cactus build: a label-propagation pass that clusters the graph, contracts the clusters into super-nodes, and reads the contracted graph's minimum degree as an upper bound on \(\lambda\). The cactus pipeline then runs against that tighter bound, which lets the contraction phases prune more aggressively.

The LP body is the standard semi-synchronous label-propagation step. Initialise every node with its own label; for two iterations, walk the nodes in a chunk-shuffled order; for each node, sum incoming edge weight per neighbour-label, pick the heaviest. Tie-break is one fair coin per equal-weight pair (one next() % 2 draw on each tie).

The shuffle is local. Rather than a single global Fisher-Yates over all \(n\) positions, VieCut shuffles each contiguous chunk of 128 positions in place. This calls std::shuffle's optimised branch, which pulls roughly one RNG draw per swap; on \(n = 22963\) the LP path alone consumes around \(99{\small,}000\) draws per iteration. The byte-equal port hand-replicates the libstdc++ pairwise-swap order, so the JS walker consumes RNG in the same order as the C++ tracer.

After two LP iterations the graph is re-indexed by encounter order, then a findTrivialCuts sweep peels small blocks whose contracted node degree falls below the current mincut estimate, then the result is contracted into a super-graph. PR12 and PR34 fire on the super-graph for one more pass each. The loop continues while the super-graph still has more than 10000 nodes and the previous iteration actually shrank it.

a small head-scratcher

The LP body does not draw RNG when one block strictly beats the rest; the draw only fires on equal-weight ties. This is a deliberate short-circuit in the canonical source and was the trickiest part of getting the byte-equal port to match: on a graph with many strict winners the RNG stream stays untouched for long stretches, while on a graph with many ties (e.g. binary edge weights and roughly balanced communities) the stream advances rapidly. The walker on this page runs at \(n = 8\) and never enters the LP-loop path, but the kernel exposes it for the \(n > 10000\) fixtures the verification harness runs against.

edge cases

Branches the walker may not show.

What if \(\lambda = 0\)?

The graph is already disconnected. The driver short-circuits before Phase E and returns the existing components as the partition; the cactus build never runs. WCC and CM treat this case as the trivial-skip path; the SBM-Flat-PP per-cluster stress panel exercises it 10285 times across 153 cells.

What if \(n = 2\)?

Recursion base case inside the cactus build. A two-node graph has exactly one minimum cut, so the cactus is just two cactus nodes joined by a single tree edge of weight \(\lambda\).

What if shrinkage is below 1%?

The outer-while loop exits. The four contraction phases stop reducing the graph, so control passes to the recursive cactus build with whatever super-graph the loop left behind.

What if the singleton-cut variant fires?

When push-relabel finds max_flow = \(\lambda\), the SCC decomposition produces two components, and one of \(\deg(s), \deg(t)\) equals \(\lambda\), the cactus build takes a special branch (stage 4 callout above). The contracted side becomes one cactus node and is reattached as a singleton after the recursion returns.

used by

VieCut's place in the gallery.

VieCut is a primitive, not a clustering algorithm itself. It is the mincut backend other post-processors call when they need an exact global minimum cut on a cluster:

  • WCC calls VieCut on every cluster to check whether the cluster's intra-edge mincut clears a connectivity threshold; clusters that fail get split along the most-balanced cut and re-checked recursively.
  • CM does the same well-connectedness check, and additionally re-clusters each half with the base algorithm (Leiden or Louvain) before re-checking, which lets a deeper recursion expose smaller well-connected pieces.

Both pipelines are byte-equal verified against the canonical constrained-clustering binary because the VieCut kernel under them is byte-equal verified against the canonical VieCut/build/mincut tracer.
