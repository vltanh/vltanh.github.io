VieCut

cactus mincut + balanced-cut tie-break · Henzinger-Noe-Schulz-Strash 2018

The minimum-cut engine under WCC + CM. Computes the global minimum edge cut of a graph in (near-)linear time using the cactus representation, then picks the most balanced cut among ties.

Take a connected graph. The minimum cut is the smallest set of edges you can remove to disconnect it. The cardinality of that set (k) is the graph's edge connectivity. Any algorithm that asks "is this cluster well-connected?" reduces to: how big is its mincut?

The naive way is Stoer-Wagner: iteratively pick a node, contract a phase, record the cut, repeat. \(O(V \cdot E)\) for a single cut. Fine for small graphs; slow on real networks where you need the cut for every cluster as part of an iterative recursion (which is exactly what WCC and CM do).

VieCut (Henzinger, Noe, Schulz, Strash, ALENEX 2018) does it differently. The cactus algorithm builds a cactus representation of the graph: a tree-of-cycles where every minimum cut in the original graph corresponds to either an edge-cut in the tree or a 2-edge cut crossing one of the cycles. Computing the cactus is near-linear in V + E, after which every minimum cut is a tree path or cycle pair away. Practical speedup over Stoer-Wagner: 10-100x on million-node networks.

why this matters for WCC + CM

WCC and CM call mincut on every cluster, recursively. On a network with k clusters of average size n/k, that's k mincut calls per round, times the recursion depth. Stoer-Wagner makes the post-proc pipeline scale as \(O(V \cdot E^2)\) on bad inputs; VieCut's cactus drops it to \(O(V \cdot E \log V)\) typical.

The other VieCut win is most-balanced-cut tie-break. When multiple cuts have the same minimum cardinality (which happens often: any pendant or whisker creates a cut of size 1, but so does the genuine community boundary), VieCut picks the cut that splits the graph most evenly. Stoer-Wagner picks whichever cut its phase happens to land on first. The split selection determines what gets pushed back into WCC's recursion, which determines whether the recursion converges quickly or peels nodes one at a time.

Why most-balanced-cut?

Imagine a cluster with two dense halves joined by a single bridge edge. The mincut is 1 (cut the bridge). Two valid bipartitions exist:

  • Balanced: split into the two halves directly.
  • Pendant: peel off one isolated node + leave the rest connected. Also a cut of 1, but useless.

If the cluster has additional pendants or whiskers (rare in dense parts of social networks; common in sparse parts), the mincut between any pendant and the bulk is also 1. VieCut's tie-break picks the balanced cut so WCC's recursion makes structural progress instead of stripping a node per round.

The 32-node fixture's cluster A is a small example. A's mincut is 1 (multiple cuts achieve it: the periphery's bridges to the K_5 core all have cardinality 1). With Stoer-Wagner, you peel one periphery node per round; recursion ends after several rounds. With VieCut + balanced selection, you split the periphery from the core in one move. Same final partition (both end at the K_5 core as the well-connected residual when the threshold is \(\log_{10}(n)\)) but different intermediate trace.

The cactus, conceptually

Karzanov's 1973 result: in any graph G, all minimum cuts can be encoded by a cactus tree T where:

  • Each node in T represents a contracted set of original-graph nodes.
  • Each edge in T represents a cut of cardinality k (= the global mincut).
  • Each cycle in T represents a family of cuts of cardinality k that share two edges of the cycle.

So if you find any minimum cut by classical Stoer-Wagner-like contraction, you've found one edge of the cactus. To find them all (so you can pick the most balanced one), you contract the discovered min-cut sides + recurse. VieCut's cactus_mincut is a careful implementation of this recursive cactus build, with engineering for cache locality, edge contraction efficiency, and parallelism.

On the gallery's 32-node fixture this is overkill; on a million-node co-citation network it is what makes WCC tractable.
