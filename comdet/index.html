Community-Detection Algorithms

A gallery of community-detection algorithms and post-processors walked stage by stage on the same small input. Each takes an unlabelled network and emits a partition of its nodes; what counts as a community differs from one method to the next.

notes netgen source

Given a network \(G\) (undirected, unweighted, simple) with no labels on its nodes, we want a partition \(\hat{\mathcal{C}}\) that groups the nodes into communities. Community means different things to different algorithms: a tightly-knit modularity peak, a short codelength under a random-walk encoding, a high-\(k\) core, or a posterior block under a generative model. Each algorithm here picks one definition and optimises it.

Different algorithms agree on the obvious cases and disagree on the boundaries. The same input network produces a different number of clusters, different boundaries, and a different singleton set under each method. The gallery exists to make that disagreement visible: every page walks one algorithm from input to output on the same 32-node fixture, keeps one interactive widget per stage, and shows the partition next to the planted ground truth.

Two labels recur across the pages: a node either lands in a non-trivial cluster the algorithm found, or stands alone, and algorithms treat the two cases differently.

cluster: group of size ≥ 2 in the algorithm's output partition.
outlier: node dropped from the partition, either unassigned by the algorithm or surviving alone in a singleton that gets pruned pre-write.

Every algorithm runs a single base stage that emits its com.csv. Optional post-processors run downstream of the base, each consuming the previous partition and tightening it under a constraint:

  1. CC splits any internally-disconnected cluster into its connected components.
  2. WCC mincuts each cluster and splits when the cut falls below a connectedness threshold (\(\log n\) by default; \(\sqrt{n}\) on the sqrt criterion).
  3. CM mincuts, splits, then re-runs the base algorithm on each piece, repeating to a fixed point.

Each algorithm only accepts the post-procs that make sense for it: SBM gets CC + WCC, Leiden gets CM, IKC gets none, Infomap gets CC.

Optimisation-based

Pick a quality function on partitions and walk a local search over partitions until no move improves it. Modularity and CPM are the two objectives in shipping use; Leiden is the optimiser of choice for both since it fixes Louvain's badly-connected-community failure mode via a refinement phase.

Leiden-CPM Leiden with constant Potts model
paper · code
Local-move, refinement, aggregation, repeat. CPM trades the resolution-limit problem of modularity for a tunable resolution \(\gamma\): high \(\gamma\) splits, low \(\gamma\) merges. Leiden's refinement phase guarantees every output community is internally well-connected.
Leiden-Mod Leiden with modularity
paper · code
Same optimiser, modularity objective. Inherits modularity's resolution limit: communities below a size threshold get absorbed into larger ones whether the network wants them to or not. Workable on small graphs; degrades on large sparse ones.

Information-theoretic

Encode a random walk on \(G\) using a two-level prefix code: one set of code words per module plus one set per node within a module. The optimum partition is the one whose codelength \(L(M)\) is shortest. Communities are flow traps.

Infomap map equation on PageRank flow
paper · code
Smart-teleportation PageRank gives the per-node flow; the map equation \(L(M)\) measures the codelength a random walker spends inside vs. between modules. Greedy joining shrinks \(L(M)\); fine + coarse tuning escapes local minima; recursion builds the hierarchy.

K-core peeling

Repeatedly extract the \(k\)-core (the maximal subgraph where every node has degree \(\ge k\)) and call each connected piece a community. Drop everything that fails a minimum-density check.

IKC iterative k-core decomposition
unpublished · code
Take the \(k\)-core for the largest \(k\) that still contains \(\ge\) one node, peel off the connected components, gate each on a modularity threshold. Drops nodes that never qualify. Tightest of the bunch on coverage, loosest on recall.

Generative (Bayesian SBM)

Posit a generative model where edges between blocks follow a Poisson rate, then find the partition that maximises the posterior. Variants change the prior (planted vs. uniform) and whether the model corrects for the degree sequence. Nested variants compose flat SBMs across hierarchy levels.

SBM-flat-dc degree-corrected stochastic block model
paper · code
Flat SBM with degree correction. Multilevel MCMC alternates merge sweeps that shrink the partition and Metropolis-Hastings sweeps that move single nodes. The deg-corr prior absorbs degree heterogeneity into the model so heavy-tailed nodes don't get their own block.
SBM-flat-ndc non-degree-corrected SBM
paper · code
Same multilevel MCMC, no degree correction. Hubs end up flagged as their own block. Useful when degree variance carries community signal that deg-corr would otherwise factor out.
SBM-flat-pp planted-partition SBM
paper · code
Specialised SBM with one rate inside blocks and one rate between them. Strong assortativity prior; favours partitions where every block looks the same shape. Trips on networks where some blocks are sparse and others dense.
SBM-nested-dc hierarchical degree-corrected SBM
paper · code
Stack of flat deg-corrected SBMs, level \(l\) treating level \(l\!-\!1\)'s block-graph as input. Defeats the resolution limit by encoding small-cluster structure at the lowest level + coarse cluster structure at higher ones. Ground-truth comparison uses level 0.
SBM-nested-ndc hierarchical non-degree-corrected SBM
paper · code
Hierarchical SBM without degree correction. Pairs the resolution-limit fix with the degree-blind prior. Hubs may form their own first-level blocks before getting absorbed up the hierarchy.
SBM-flat-best flat SBM, lowest entropy
meta · code
Runs flat-dc, flat-ndc, and flat-pp; picks the one whose model entropy is lowest; symlinks downstream. The default flat-SBM picker when there's no prior reason to prefer one variant.
SBM-nested-best nested SBM, lowest entropy
meta · code
Same selector for the nested family: nested-dc vs. nested-ndc, lowest entropy wins. Hierarchy preserved through the symlink.

Post-processors

Three constraints applied downstream of any base partition. Each tightens what the base produced, never adds nodes back. CM is the only one that re-runs the base optimiser; CC and WCC are pure split operations.

CC connected-component split
code
Walk every cluster's induced subgraph, split it into weakly-connected components, write each as its own cluster. Catches algorithms that assigned a label without checking connectivity (SBM is the usual culprit). Pure BFS, no model parameters.
WCC well-connected components
paper · code
Stronger than CC: a cluster passes only if its mincut exceeds a connectedness threshold (\(\log_{10} n\) on the log criterion, \(0.2\sqrt{n}\) on sqrt). Anything weaker gets recursively mincut and split. VieCut's cactus algorithm runs the cuts.
CM connectivity modifier
paper · code
WCC's recursive split, plus a re-run of the base algorithm (Leiden CPM or Mod) on each piece after the cut. Repeats to a fixed point: every output cluster is well-connected and locally-optimal under the base objective. Heaviest of the three.
