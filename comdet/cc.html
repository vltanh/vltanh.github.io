CC

connected components · Park 2025 / Vu-Le 2026

Cheapest of the three connectivity post-procs. One BFS per cluster; every connected piece becomes its own output cluster. No threshold, no parameters: a sanity pass that catches partitions whose clusters are not actually connected.

Walker pending. The per-stage walker for CC waits on the Phase 4c JS kernel port. Today the page surfaces the input fixture and the planned stage list; interactive widgets land per-stage as the port catches up to canonical. The technical companion at docs/algorithms/cc.md covers source pointers, CLI flags, and determinism guarantees.

Some clustering algorithms emit a label per node and call it a day. They do not check whether the nodes carrying that label are actually reachable from each other. SBM is the usual offender: stochastic block models care about edge density between blocks, not about whether each block is internally connected. So a cluster can have, say, two disconnected halves with the same label, and the output looks like one community when it is really two.

CC is the patch. For each cluster C in the input partition, take the subgraph induced by C's nodes (drop every edge crossing out to a different cluster), run a BFS, and replace C with one new cluster per connected piece. If C was already connected, nothing changes.

The cost is one BFS per cluster: \(O(|V| + |E|)\) over the whole graph. There are no parameters and no model.

why this matters · Park 2025 / Vu-Le 2026

On graph-tool's flat and nested SBMs (every variant tested: degree-corrected, non-degree-corrected, planted-partition, plus PySBM), internally disconnected clusters show up across both real and synthetic benchmarks. Splitting them with CC improves accuracy on most of those benchmarks. WCC adds a threshold on top and gains more; CM adds a re-clustering pass on top of that and gains the most. CC is the cheapest correction of the three.

The shipped binary is constrained_clustering MincutOnly --connectedness-criterion 0. The 0 selects the Simple branch in mincut_only.cpp: short-circuit the recursive cut + threshold loop and emit each component directly. Same code path as WCC, just with the cut step disabled.

stage 1 · per-cluster BFS

One traversal per input cluster, on the intra-cluster subgraph.

Walk through the input clusters in id order. For each, drop every edge crossing to a different cluster, BFS the residual, and emit one component per BFS root. Singletons are dropped silently (constrained.h:409 size > 1 filter); components of size ≥ 2 carry forward as fresh output clusters.
