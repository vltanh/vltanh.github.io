CC

connected components · Park 2025 / Vu-Le 2026

Cheapest of the three connectivity post-procs. One BFS per cluster; every connected piece becomes its own output cluster. No threshold, no parameters: a sanity pass that catches partitions whose clusters are not actually connected.

Some clustering algorithms emit a label per node and call it a day. They do not check whether the nodes carrying that label are actually reachable from each other. Stochastic block models are the usual offender: they care about edge density between blocks, not about whether each block is internally connected. A cluster can end up as two disconnected halves under the same label, and the output looks like one community when it is really two.

CC is the patch. For each cluster in the input partition, take the subgraph induced by that cluster's nodes (drop every edge crossing out to a different cluster), run a breadth-first search, and replace the cluster with one new cluster per connected piece. If the cluster was already connected, nothing changes.

The cost is one breadth-first search per cluster, \(O(|V| + |E|)\) over the whole graph. In plain terms: every node and every intra-cluster edge gets touched once, no more. Two interesting properties: cost is independent of the number of input clusters (the BFS sweeps the residual graph in one pass over the whole node set); and there is no parameter to tune, no threshold to set, no model to fit.

cross-cluster edge an edge whose endpoints carry different input cluster labels. CC drops every such edge before the breadth-first search.
residual graph the subgraph that survives after the cross-cluster edges are dropped. Same node set as the input; only intra-cluster edges remain.
singleton component a connected component of size one in the residual. CC drops these from the output; nodes that fall into a singleton end up unlabelled.
why this matters · Park 2025 / Vu-Le 2026

On graph-tool's flat and nested stochastic block models (every variant tested: degree-corrected, non-degree-corrected, planted-partition, plus PySBM), internally disconnected clusters show up across both real and synthetic benchmarks. Splitting them with CC improves accuracy on most of those benchmarks. WCC adds a connectedness threshold on top and gains more; CM adds a re-clustering pass on top of that and gains the most. CC is the cheapest correction of the three.

CC ships as the same binary that hosts WCC and CM, invoked with the threshold disabled. The threshold path collapses to a short-circuit: emit every connected component of the residual graph directly, skip the recursive cut + threshold loop that the other two run. stage 2 · edge cases

What CC does at the corners.

Three corner cases the walker glides past on the planted fixture but that the algorithm has to handle in production.

A cluster with no internal edges.
Every cross-cluster edge gets dropped, so the cluster's residual subgraph has no edges left. Each node sits on its own. The breadth-first search reaches nothing past its starting node. Every node becomes a singleton, the singleton filter drops them all, and the cluster vanishes from the output.
A single-node cluster.
One root, one component of size one, dropped at the filter. CC treats outliers and singletons identically: gone from the output. The fixture's nodes 30 and 31 sit in cluster −1 and follow this path.
A cluster already connected.
The breadth-first search from the lowest-id node reaches every other node in one sweep. No splits, no drops. The cluster passes through unchanged, picking up a fresh output id assigned in the order the components are discovered. Cluster A in the fixture is this case.
Why CC matters for the rest of the gallery: WCC and CM both start from this same residual graph + per-cluster BFS. CC is the bare floor; WCC adds a connectedness threshold and CM adds a re-clustering pass on top.
