ABCD+o

ABCD with an explicit outlier block. Outliers have only external stubs and cannot connect to each other.

Plain ABCD folds unclustered nodes into singletons which get filtered out of com.csv. For graphs where the "background" is real and meaningful (bots, sensors, drive-bys), that is a silent loss. ABCD+o promotes the background into a first-class outlier block, cluster_id=1, with two constraints baked into the sampler.

First: outliers have $$d_i^{\text{int}} = 0$$. All their stubs are external. The model pins this: you do not get to argue.

Second: outliers cannot pair with each other. The external configuration model is constrained so every outlier stub pairs with a non-outlier stub. Our input has an edge between outliers 19 and 20; that edge is dropped at profile time because the sampler cannot reproduce it.

stage 1 · profile

Count the outliers separately.

The profile step writes four things instead of three: degree.csv, cluster_sizes.csv (real clusters only), mixing_parameter.txt, and n_outliers.txt. The outlier count is what the sampler prepends to the cluster-size list to become cluster_id=1. On our small input: two outliers, so cluster_sizes becomes $$[2, 8, 6, 4]$$ at the sampler's door.

why drop_oo=true by default

The sampler cannot emit outlier-to-outlier edges. If the profile counted them in the degree sequence, the sampler would be asked to produce degrees it cannot fulfil, and $$\xi$$ would drift. Dropping OO edges at profile time makes the stats achievable. ABCD+o is the one generator in the repo that flips drop_outlier_outlier_edges to true by default.

stage 2 · outlier constraint on ξ split

Outliers are pinned: every stub is external.

Plain ABCD splits each degree $$d_i^{\text{ext}} = \text{round}(\xi \cdot d_i)$$. ABCD+o overrides this for outliers: $$d_{19}^{\text{ext}} = d_{19} = 2$$ and $$d_{19}^{\text{int}} = 0$$, and the same for 20. Slide $$\xi$$ to see non-outliers repartition normally while outliers stay 100% red.

stage 3 · external pairing with OO-exclusion

Outlier stubs can only pair with non-outlier stubs.

The external configuration model pairs stubs from a global pool. ABCD+o constrains this: every outlier stub must pair with a non-outlier stub. Exactly how the Julia sampler enforces the constraint (two-pool matching, rejection with retry, or another scheme) is an implementation detail inside the sampler; the contract it exposes is that no outlier-outlier edge can appear in the output.

stage 4 · the warning branch

If $$\xi$$ is small, the outlier block might look like a community.

At low $\xi$ with a large outlier block, the non-outlier side of the external pool is small, so many non-outliers end up with several outlier neighbours. Two outliers that share enough non-outlier neighbours look, to a modularity-style detector, like members of the same community, even though no outlier-outlier edge was ever drawn. The Julia sampler detects this pattern and writes "outlier nodes form a community" to stderr. The Python wrapper branches:

If the warning fires, keep cluster_id=1 rows in com.csv: the outliers are a community in the output. If it does not fire, filter cluster_id=1 out: outliers appear in edge.csv but not in com.csv. Slide $\xi$ below 0.10 to simulate the warning firing.

branch affects semantics

Downstream tools that read com.csv see a different partition depending on whether the warning fired. The effect is load-bearing: a visualization of ABCD+o output should always surface the warning status, otherwise it is ambiguous whether an outlier node with no cluster_id is "an outlier by design" or "an outlier that got lifted and you forgot to check".
