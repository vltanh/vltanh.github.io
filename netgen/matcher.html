network-generation · shared utility

degree matchers

A shared top-up toolkit every generator can call after its main pass. Reads two edgelists (current graph + reference target), finds per-node residual deficits, and adds edges that close the gap. Four algorithm families, each with a cluster-preserving twin, and a stacking driver that lets one algorithm clean up what the previous one could not place.

Every generator in this project ends with an output that is "close to" the input degree sequence but not exact. Dedup, rewire, and outlier handling each remove a few stubs from each node's target. The matcher's job is the last one in line: pop the node still missing the most edges, find a partner that also still has room and is not already connected to it, drop the edge in. Repeat until either the deficit list is empty or every remaining pair is blocked.

That last word, "blocked", is where the algorithm choices matter. The same residual can be drained several different ways, and they disagree on which pairs to try, in what order, and what to do when a deficit cannot be closed cleanly. The choices show up in the output degree sequence and in how many stubs end up unplaced. On top of that, each algorithm has a cluster-preserving twin that adds a second budget — a per-(block, block) edge cap derived from the reference clustering — so the matcher cannot trade block-level structure for closing the degree gap.

Any sequence of matchers can be stacked. The CLI accepts a comma-separated list; each algorithm runs in turn on the residual the previous one left behind. A single name is a one-step stack. Two-step chains pair a stochastic bulk drain with a deterministic tail; longer chains compose cluster-preserving and plain passes when degree mass and cluster structure both matter.

input contract

Two edgelists in. Top-up edges out.

The matcher takes two inputs that share a node set: the current graph (the generator's output so far) and a reference graph (whose degree sequence is the target). For each node it computes the residual deficit:

\[ r_u \;=\; \max\bigl(0, \,d_u^{\text{ref}} - d_u^{\text{input}}\bigr), \]

where \(d_u^{\text{ref}}\) is \(u\)'s degree in the reference and \(d_u^{\text{input}}\) is its degree in the current graph. The matcher's job is to add new edges so that, post-match, \(d_u^{\text{out}} \approx d_u^{\text{ref}}\) for every node. It can never reduce a degree; if some node already has more edges than its target, the matcher leaves it alone.

The matcher is selected by name. A single name picks one algorithm; a comma-separated list picks a stack — each algorithm runs in turn on the residual the previous one left behind. Cluster-preserving algorithms additionally consume the reference clustering and a derived per-(block, block) edge budget; non-cluster-preserving ones do not need it. The pipelines that wrap the matcher take care of attaching the clustering files when any step in the stack is cluster-preserving.

when each generator calls it

EC-SBM-v1 uses greedy for byte-stable output against its reference implementation. EC-SBM-v2 and EC-SBM-v3 default to cluster_preserving_true_greedy. The standalone SBM generator defaults to the same. ABCD, ABCD+o, LFR, and nPSO leave the matcher off by default; their pipelines turn it on as an opt-in step, usually paired with the --remap mode covered at the bottom of the page (their output node IDs do not align with the input's).

the four families · overview

Different ways to drain the same deficit pile.

All four families share the same outer loop: pick a node with positive deficit, pick a partner that also still has room and is not already adjacent, add the edge, decrement both. They differ on the picking order, on whether the partner is chosen deterministically or by a weighted random draw, and on what they do when the loop stalls.

familyhow it picks pairsfailure mode
greedy Take the most-needy node. Take its first acceptable partner in id-ascending order. Repeat until that node's deficit is closed, then move on. Silent gridlock: when no partner is left it drops the remaining stubs without logging.
true_greedy (default) Take the most-needy node. Take the partner that is itself currently most needy, breaking ties by id. Push the updated needs back into the priority order before the next pick. Logs gridlock when no partner with positive deficit is left.
random_greedy Pick the source node by a weighted random draw over residuals. Pick the partner the same way over valid targets. Logs gridlock. Useful for measuring how much of greedy's output comes from the deterministic ordering.
rewire Make one stub per missing edge per node, shuffle the pile, pair adjacent stubs. Self-loops, parallels, and duplicates queue for a 2-opt repair pass that swaps endpoints with a random valid edge until the queue is empty or a retry budget is hit. Logs gridlock. Almost always resolves on realistic inputs; the repair pass is the slow path on hub-heavy graphs.

The table reads as a spectrum from determinism to randomness. Greedy and true_greedy produce the same output every run on the same input (no seed needed). Random_greedy and rewire sample fresh draws each call. True_greedy is the default: it closes the residual deterministically with negligible drop on realistic inputs.

Each family also has a cluster-preserving twin (cluster_preserving_greedy, cluster_preserving_true_greedy, and so on). The twin runs the same outer loop but adds one rule: a candidate partner is rejected if the (block, block) bucket of the pair has zero edges left in its budget. The budget is built once at the start, from the reference clustering's per-(block, block) edge counts minus what the current graph already has, and decremented every time the matcher accepts an edge. The four merged sections below describe each family and then how the cluster-preserving twin changes its behaviour. family · greedy

Take the most-needy node. Drain it against an id-sorted partner list.

The matcher v1 of this project shipped with. Each step pulls out the node with the largest deficit, builds the list of candidate partners (every other node that still has room and is not already adjacent to it), sorts that list by id ascending, and walks down it adding edges until either the source node's deficit is closed or the candidate list runs out. Once one node is fully drained the loop moves on to the next-most-needy one. Stubs that cannot be placed because no partner is left disappear without any log line — the "silent gridlock" failure mode.

The walker below replays one such drain per step. The caption names the partner picked at each draw. The output is deterministic because the source order, the partner sort, and the tie-break rule are all fixed; the same input gives the same output every run, no seed needed.

caveat: silent gridlock

If a node is starved (no valid partner with deficit), greedy drops the remaining stubs without logging. The achieved degree drifts below the target, and downstream tools cannot tell whether a node "really" lost edges or got starved by the matcher. The other three families log gridlock as a warning.

cluster-preserving twin

The cluster-preserving variant runs the same outer loop and the same id-sorted partner list, then layers one extra rule on top: a candidate partner is removed from the list before the walk down it begins if the (block, block) bucket of the pair has zero edges left in its budget. The budget is computed once at the start from the reference clustering's per-(block, block) edge counts minus what the current graph already has. Each accepted edge decrements the corresponding bucket. When a bucket hits zero, candidates whose pair lands in that bucket disappear from future partner lists.

Effect: edges land where the reference clustering wants them — intra-block when its budget is healthy, inter-block when the inter budget is non-empty — at the cost of more starvation. Because greedy already swallows starvation silently, this twin can drop a noticeable number of stubs on inputs whose deficit is concentrated in a few blocks; the dropped stubs surface in the final output's degree drift, not in the log. family · true_greedy

Take the most-needy node. Pair it with the partner that itself is most needy.

The default matcher. Same source pick as greedy (the node with the largest deficit goes first), but the partner is chosen differently: among the valid candidates (still has room, not already adjacent), pick the one whose own deficit is largest, breaking ties by id ascending. After each accepted edge, both endpoints' updated deficits go back into the priority order so subsequent picks see fresh values rather than stale ones from the start of the burst.

The change from greedy is small but consequential. Greedy commits to one source until it is fully drained or stuck, blind to whether its partners are running out of room. True_greedy lets the priorities re-shuffle after every edge, so the matcher always works on the currently neediest pair. On uneven deficits this closes the gap with substantially fewer dropped stubs. Gridlock — when no candidate with positive deficit is left — is logged as a warning rather than swallowed.

cluster-preserving twin

Same priority-driven source pick and partner pick as the global true_greedy. The twin filters the candidate list before scanning it: any candidate whose (block, block) bucket has zero edges left in its budget is excluded. The first candidate that maximises remaining deficit and respects the budget gets the edge, and the budget for that bucket goes down by one. Gridlock now triggers when no in-budget candidate with positive deficit is left, and is logged.

Because the source still pulls the most-needy node first and re-shuffles after every accept, the twin loses fewer stubs to starvation than the cluster-preserving greedy does. On the bench in externals/ec-sbm/examples/bench/, this is the algorithm EC-SBM v2 uses, and its loss to budget exhaustion is around 0.5% of total edges on networks in the 100K–200K node range. Where that 0.5% matters, the stack section below shows how to recover it without giving up cluster-level fidelity.

family · random_greedy

Pick both endpoints by weighted random draw.

Same outer loop, but every choice is a weighted random draw. The source node is sampled with probability proportional to its current deficit; among the valid candidates the partner is sampled the same way. The two random picks are independent, both keyed off the same seed.

This family exists mostly to measure how much of greedy and true_greedy's output is artifact of their tie-break rules. Running random_greedy with several different seeds and comparing the spread is the cleanest way to see which output features are pinned by the input deficit and which are pinned by the deterministic ordering. Gridlock is logged. Step count varies between seeds because the order in which nodes get starved changes.

family · rewire

Make a stub per missing edge, shuffle, pair adjacent. Repair conflicts.

The configuration-model approach. The matcher imagines a small bag of half-edges, called stubs: each node contributes one stub for every edge it is still missing. The whole bag is shuffled and stubs are paired up two-at-a-time, each pair becoming an edge. Some pairs are invalid — a self-loop, a duplicate of an edge that already exists, or a duplicate within this same pairing. Those land in a repair queue.

The repair phase is a 2-opt swap. For every invalid pair the matcher pulls a random valid edge from the existing pile and tries the four endpoint recombinations: if any of them produces two valid edges, the swap is accepted and both pairs join the valid pile. If none works the pair goes back on the queue for a later attempt. The phase runs for a fixed retry budget; whatever still conflicts at the end is logged and dropped.

The shuffle is the only source of variation across seeds. On dense inputs almost every pairing is valid on the first pass and the repair queue stays short. On long-tailed inputs with hubs, several pairs land invalid (the same hub gets two stubs that pair together) and the repair pass walks them.

cluster-preserving twin

Same idea, but the stub bag is partitioned by (block, block) bucket up front: each bucket's budget tells the matcher how many edges that pair is allowed to receive, and stubs are drawn from each bucket independently. The 2-opt repair phase respects the partition, only swapping endpoints in ways that keep both repaired pairs inside their original buckets. Whatever still conflicts at the retry budget is logged and dropped, just as in the global rewire.

The walker is algorithmically faithful to the production code but does not byte-equal it: production delegates the per-bucket stub draw to graph-tool, whose random number generator is not portable to a browser. The page uses a JavaScript-native weighted draw with the same control flow, so the per-step decisions read identically even when the seeds do not.

stackable matchers

Chain matchers. Each one cleans up what the previous left behind.

The four families above and their cluster-preserving twins are not exclusive. The matcher CLI accepts a comma-separated list of algorithm names, runs them in order, and feeds whatever stubs are still unplaced from one step into the next. A single name is a one-element stack. A two-name list pairs a bulk drain with a finishing pass: the first algorithm closes the easy edges, the second mops up the tail. Three or more elements are a longer chain.

Each step uses its own random seed, derived from the matcher's overall seed, so randomness in one step does not bleed into the priorities of the next. The shared state across steps is the running graph itself plus the deficit dictionary, both updated as edges land. Cluster-preserving steps additionally share the per-(block, block) edge budget, which every cluster-preserving step in the chain decrements; non-cluster-preserving steps ignore the budget entirely. Putting a non-cluster-preserving step after a cluster-preserving one is the way to recover degree mass that the budget gate refused, at the cost of letting that final step place a few edges in buckets the cluster-preserving steps would have refused.

stacks worth knowing

rewire, true_greedy — stochastic bulk drain, deterministic tail.

cluster_preserving_rewire, cluster_preserving_true_greedy — same shape, every step gated by the bucket budget.

cluster_preserving_true_greedy, true_greedy — cluster-preserving first, then plain. Closes the residual degree gap that the budget gate refused, at a measurable cost to cluster-shape stats (see the warning below).

cluster_preserving_rewire, cluster_preserving_true_greedy, true_greedy — the most thorough chain. Stochastic bulk drain inside the buckets, deterministic in-bucket cleanup, then a plain finishing pass on whatever the buckets refused.

stacking is not a free win

A 33-network sweep on EC-SBM v2 against leiden-cpm-0.0001 (full report at externals/ec-sbm/examples/bench_stack/report.md) found:

  • The two-step stack closes degree mass — n_edges gap drops from ~0.5% (single CP-TG) to ~0.4% — but conductance EMD goes 5x worse, mixing-parameter EMD 2x worse, and connected-component sizes drift away from the reference. Paired Wilcoxon p < 1e-4 on every cluster-shape metric.
  • The three-step stack does not improve the trade-off; it is faster (CP-rewire batches stub draws) but regresses the same cluster-shape stats further.

Use the single cluster_preserving_true_greedy when cluster-shape fidelity is the priority and a 0.5% degree-mass gap is acceptable. Use the stack when degree exactness matters more than cluster boundaries (for example, downstream code that asserts on exact m, or generators with heavily-refined clusterings where the budget gate disconnects small clusters — see the douban / piecewise note in externals/ec-sbm/examples/bench/report.md).

case study · dnc

Pick the matcher off a graph that loses 29% of its edges to dedup.

The dnc network has 1,891 nodes, 5 reference clusters, and 10,429 reference edges. Run the standalone SBM generator on that input with seed 1: graph-tool's stub-pair sampler hits enough collisions on the dense intra-cluster blocks that, after self-loops and duplicates are removed, only 7,438 edges survive. The matcher's job is to top up 2,991 missing edges — a 29% deficit, almost entirely concentrated inside cluster interiors because that is where the SBM's parallel-edge collisions concentrate.

Four matcher choices, same SBM output, same seed:

matcherfinal edgesdeficit closedcluster fidelity
true_greedy 10,429 100% (zero residual) No bucket gate. Hubs deep inside one cluster reach across to outliers in another whenever no closer partner is left, so the block-pair edge counts drift away from the reference.
cluster_preserving_true_greedy 10,155 90.8% (274 stubs stuck) Bucket gate enforced strictly. Edges land where the reference says they should, but 274 stubs are abandoned because the buckets they would consume are already exhausted by the time their partner becomes the priority pick.
cluster_preserving_true_greedy, true_greedy 10,340 97.0% (89 stubs stuck) Cluster-preserving pass first; plain pass picks up the residual. Recovers 185 of the 274 edges the gate refused. The 185 cleanup edges land in buckets the cluster-preserving step had used up, so block-pair fidelity is slightly looser than the gated-only run, but vastly closer to the reference than plain true_greedy.
cluster_preserving_rewire, cluster_preserving_true_greedy, true_greedy 10,347 97.1% (82 stubs stuck) Same as the two-step stack, plus a stochastic bulk drain at the front. The 2-opt repair has more room to manoeuvre while the buckets are still mostly full, so the cluster-preserving true-greedy step has fewer hard cases to handle. Marginal extra recovery (7 more edges) on dnc; the gain grows on graphs where the deficit is more skewed.

The dnc table makes stacking look like a clean win on closing the deficit. The 33-network bench in externals/ec-sbm/examples/bench_stack/report.md shows a different picture: the cleanup edges land outside the reference clustering's per-block budgets, which is exactly what the budget gate was trying to prevent. Conductance EMD goes 5x worse, mixing-parameter EMD 2x worse, and connected-component sizes drift away from the reference. So the stack closes degree mass at a meaningful cost to the very cluster-shape stats the cluster-preserving family was designed for.

The dnc fixture is small enough that the cleanup spike does not dominate the per-net averages. On real benchmark networks (10K–200K nodes) the regression on cluster-shape stats is significant at α = 0.01 across nearly every relevant metric. Default to the single cluster_preserving_true_greedy matcher; reach for the stack only when one of these holds:

  • Downstream contract on exact n_edges — e.g., a comparator that asserts on m. The 0.5% deficit becomes blocking.
  • Heavily-refined clusterings (piecewise CM and similar) — small refined clusters can have tiny per-block budgets that the gate exhausts before the matcher can bridge them, leaving the cluster disconnected. The stack closes those bridge edges. See the douban / piecewise case in externals/ec-sbm/examples/bench/report.md where single CP-TG produced n_concomp SRD = 0.99 on douban; the stack closes it.

Numbers come from running run_generator.sh --generator sbm on dnc with seed 1 and toggling --degree-matcher across the four configurations above; the SBM output is identical across all four runs (same graph-tool seed) so the differences are purely matcher behaviour. The 33-network bench results referenced above use EC-SBM v2 + 5 seeds per cell with paired Wilcoxon over networks within each bucket.

the --remap option

Pair by degree rank for gens that emit fresh node IDs.

Three of the simple gens (abcd, abcd+o, lfr) and nPSO emit integer node IDs that have no relation to the input's IDs: ABCD's com.tsv uses 1, 2, ..., N, LFR's binary outputs 0, 1, ..., N-1, and nPSO's MATLAB sampler labels nodes by arrival rank. Naively diffing degrees against the input's IDs is meaningless. The --remap flag pairs nodes by degree rank: the input node at rank \(i\) (descending input-degree) is paired with the output node at rank \(i\) (descending output-degree), and the deficit is computed on that pairing.

Algorithm-side this is an accounting layer: the matcher still adds edges in the input's ID space, but it judges deficits against the rank-paired target. The pairing is the L1- and L2-optimal one (rearrangement inequality) for matching two non-identical degree sequences. There is no on-disk re-ID; the output edge.csv keeps the input's IDs throughout.

when to use --remap

Whenever the gen's stage-2 output uses fresh integer IDs that you want to align to the input's degree sequence post-hoc. The simple-gen wrappers turn it on by default whenever they enable --match-degree; the SBM family does not need it because their gens already emit edges in the input's ID space.
