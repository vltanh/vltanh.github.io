degree matchers

A shared top-up toolkit every generator can call after its main pass. Reads two edgelists (current graph + reference target), finds per-node residual deficits, and adds edges that close the gap. Five algorithms; pick by failure mode.

Every generator in this project ends with an output that is "close to" the input degree sequence but not exact. Dedup, rewire, and outlier handling each remove a few stubs from each node's target. src/match_degree.py is the shared finishing tool: pop the highest-deficit node, find a partner with deficit and no edge between them, drop the edge in. Repeat until the deficit set is empty or every remaining pair is blocked.

That last word, "blocked", is where the algorithm choices matter. The same residual can be drained five different ways, and they disagree on which pairs to try, in what order, and what to do when a deficit cannot be closed cleanly. The choices show up in the output degree sequence and in how many stubs end up unplaced.

input contract

Two edgelists in. Top-up edges out.

The CLI is generator-agnostic:

python src/match_degree.py \ --input-edgelist <current.csv> \ --ref-edgelist <target.csv> \ --match-degree-algorithm greedy|true_greedy|random_greedy|rewire|hybrid \ | cluster_preserving_{greedy|true_greedy|random_greedy|rewire|hybrid} \ --match-degree-mode global | cluster_preserving \ --output-folder <dir> \ --seed <int> \ [--remap] [--input-clustering <com.csv>] [--ref-clustering <com.csv>]

The five cluster_preserving_* variants gate every accepted edge on a per-block-pair budget derived from the reference clustering, so the matcher cannot trade block-level fidelity for closing the degree gap. They require --match-degree-mode cluster_preserving together with the input + reference clustering CSVs.

The two inputs share a node set. For each node \(u\), the residual deficit is

\[ r_u \;=\; \max\bigl(0, \,d_u^{\text{ref}} - d_u^{\text{input}}\bigr), \]

where \(d_u^{\text{ref}}\) is \(u\)'s degree in the reference and \(d_u^{\text{input}}\) is its degree in the current graph. The matcher's job is to add new edges so that, post-match, \(d_u^{\text{out}} \approx d_u^{\text{ref}}\) for every \(u\). It can never reduce a degree; if some node already has more edges than its target, the matcher leaves it alone.

when each generator calls it

EC-SBM-v1 hardcodes greedy for byte-compat with the original paper implementation. EC-SBM-v2 and EC-SBM-v3 default to cluster_preserving_true_greedy with --match-degree-mode cluster_preserving. sbm defaults to the same cluster-preserving combo. abcd / abcd+o / lfr / npso leave match-degree off by default; their pipelines accept --match-degree as an opt-in flag, paired with the optional --remap mode below for gens that emit fresh node IDs.

the five algorithms · overview

Different ways to drain the same deficit pile.

All five algorithms share the same outer loop: pick a node \(u\) with positive deficit, pick a partner \(v\) such that \((u, v)\) is not already an edge and \(v\) has positive deficit, add the edge, decrement both. They differ on the picking order and on what they do when the loop stalls.

algorithmhow it picks pairsfailure mode
greedy Heap-based. Pop \(u\) with max residual; connect to min(residual, |non-neighbours|) partners drawn via set.pop(). Silent gridlock: drops stubs without logging.
true_greedy (default) Max-heap with dynamic re-push. Pop \(u\), pick \(v\) via argmax over current degrees among valid targets, push updated residuals back. Logs gridlock when no partner is left.
random_greedy Weighted-random \(u\) (by residual), weighted-random \(v\) from valid targets. Logs gridlock; useful for comparing bias against deterministic greedy.
rewire Configuration-model pairing then 2-opt repair. Build a flat stub list (each node repeated residual times), shuffle, pair adjacent. Invalid pairs queue for run_rewire_attempts. Logs gridlock; almost always resolves on realistic inputs.
hybrid Run rewire first, then true_greedy on whatever rewire could not place. Rewire handles the bulk unbiased; greedy handles the stuck tail deterministically. Logs gridlock; drops near zero on realistic inputs.

The table reads as a spectrum from determinism to randomness. greedy and true_greedy produce the same output every run on the same input (no seed needed). random_greedy and rewire sample fresh draws each call. true_greedy is the default: dynamic re-push closes the residual deterministically with negligible drop on realistic inputs. hybrid stays available when randomized config-model pairing is preferred (rewire bulk drain + true_greedy tail).

algorithm · greedy

Heap pop, partner via id-ascending sort.

v1's matcher. Pops the node with the most missing stubs and drains it against the candidate pool. Older versions of the code used Python's set.pop() and relied on hash(n) == n for small ints to drain in slot order; the production code now sorts the candidate set explicitly by id ascending so the algorithm is deterministic across PYTHONHASHSEED values and matches this page's JS port.

Once \(u\)'s deficit is zero or partners run out, move on; unplaced stubs disappear without a log line.

def greedy(residual, adj): heap = max-heap of (residual[u], u) for u with residual[u] > 0 while heap not empty: u = heap.pop() candidates = sorted({v : v != u, v not in adj[u], residual[v] > 0}) for v in candidates[:residual[u]]: adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1 # residual[u] > 0 here means u was starved. dropped silently.

Walk the steps below. Each step pops one \(u\) and drains it; the caption names the partner picked at each draw. The "deterministic; same output every run" tag follows from the int-hash-table behaviour above. Gridlock surfaces as a "starved" event with no log message.

caveat: silent gridlock

If a node is starved (no valid partner with deficit), greedy drops the remaining stubs without logging. The achieved degree drifts below the target, and downstream tools cannot tell whether a node "really" lost edges or just got starved by the matcher. The four other algorithms below all log gridlock as a WARN.

algorithm · true_greedy

Heap pop, partner via argmax over remaining residual deficit.

Same outer pop as greedy, but the partner pick is deterministic: among valid targets (node not yet adjacent, has positive deficit), pick the one with the highest remaining residual deficit. Tie-break by id ascending. After each pair, push updated residuals back into the heap so subsequent pops see fresh values.

def true_greedy(residual, adj): heap = max-heap of (residual[u], u) for u with residual[u] > 0 while heap not empty: u = heap.pop() while residual[u] > 0: valid = {v : v != u, v not in adj[u], residual[v] > 0} if not valid: break v = argmax(valid, key=lambda v: (residual[v], -v)) # id-asc tiebreak adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1 heap.push(residual[v], v) if residual[u] > 0: log.warn(f"gridlock at u={u}, {residual[u]} stubs unplaced")

Picking by max remaining deficit biases toward the neediest nodes, draining them while they still have a wide pool of candidates. The deterministic tiebreak and explicit gridlock log are the two changes from greedy.

algorithm · random_greedy

Weighted-random pop, weighted-random partner.

Both picks are residual-weighted. \(u\) is drawn proportional to its current residual; \(v\) is drawn proportional to the residuals of valid targets (not uniform). Useful when comparing matcher bias against the deterministic algorithms: the same input run with several seeds reveals how much of the output depends on which deterministic ordering greedy and true_greedy lock in.

def random_greedy(residual, adj, rng): while any(residual[u] > 0): u = rng.choice(nodes, weights=residual) # residual-weighted valid = {v : v != u, v not in adj[u], residual[v] > 0} if not valid: log.warn(f"gridlock at u={u}, {residual[u]} stubs unplaced") residual[u] = 0 # abandon this node continue v = rng.choice(valid, weights=[residual[n] for n in valid]) # residual-weighted adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1

Each random click reseeds and reruns the algorithm; stepping through reveals how the picks differ across seeds. Step counts vary because gridlock-and-abandon makes the algorithm length depend on which u gets starved.

algorithm · rewire

Configuration-model pairing, then 2-opt repair on invalid pairs.

The unbiased one. Build a flat stub list (each node \(u\) appears residual[u] times), shuffle, pair adjacent entries. Some pairs are invalid (self-loop, already an edge, or duplicate within this pairing). Queue them, then run a 2-opt swap pass that repairs each invalid pair against a random valid edge in the queue. Stagnation detector after a fixed retry budget.

def rewire(residual, adj, rng): stubs = [u for u in nodes for _ in range(residual[u])] rng.shuffle(stubs) pairs, invalid = [], [] for i in range(0, len(stubs), 2): u, v = stubs[i], stubs[i + 1] if u == v or v in adj[u]: invalid.append((u, v)) else: pairs.append((u, v)) adj[u].add(v); adj[v].add(u) # 2-opt repair phase for attempt in range(MAX_RETRIES): if not invalid: break u, v = invalid.popleft() # FIFO over the queue x, y = rng.choice(pairs) # try swapping with valid edge (x, y) if can_swap(u, v, x, y, adj): adj[u].add(y); adj[y].add(u) adj[x].add(v); adj[v].add(x) adj[x].discard(y); adj[y].discard(x) pairs.remove((x, y)); pairs.extend([(u, y), (x, v)]) else: invalid.append((u, v)) # requeue if invalid: log.warn(f"rewire: {len(invalid)} pairs unresolved after {MAX_RETRIES}")

The shuffle is the source of variation across seeds. On dense inputs almost every pairing is valid on the first pass; the repair queue is short. On long-tailed inputs with hubs, several pairs land invalid (the same hub gets two stubs that pair together); the repair phase walks them.

algorithm · hybrid

rewire, then true_greedy on what is left.

Run rewire first to drain the bulk unbiased; whatever stubs are still unplaced after rewire's repair budget go to true_greedy for a deterministic finishing pass. Almost every realistic deficit drains to zero this way; what cannot is logged.

def hybrid(residual, adj, rng): rewire(residual, adj, rng) # phase 1: stochastic bulk drain if any(residual[u] > 0): true_greedy(residual, adj, deg) # phase 2: deterministic tail if any(residual[u] > 0): log.warn(f"hybrid: {sum(residual)} stubs unplaced after both phases")

family · cluster_preserving

The same five algorithms, gated on a per-block-pair budget.

The five algorithms above only watch per-node deficit. They pick whichever partner closes the deficit, no matter what cluster the partner sits in — which means a hub deep inside cluster C1 can drain its deficit by reaching across to a nearly-isolated outlier when nothing closer is left on the candidate list. The matched degree sequence ends up correct, but the block-pair edge counts drift away from the reference clustering's distribution.

The cluster_preserving_* family adds a second budget: a count, per (B_i, B_j) block-pair, of how many additional edges are still allowed in that pair. The matcher refuses any partner whose bp budget is empty, decrements the counter on accept, and starves nodes whose remaining stubs have no in-budget partner left. Stubs that the global family would silently drain across-cluster instead surface as gridlock; the matched degree sequence is no longer guaranteed to close cleanly, but the block-pair distribution stays loyal to the reference.

The five variants below mirror the five global algorithms one-for-one. Each takes the same residual deficit, runs its corresponding global control flow, and adds the bp filter on candidate selection plus the bp decrement on accept. Walker captions name the bp the matcher just touched and the remaining bp budget after the decrement.

algorithm · cluster_preserving_greedy

Greedy with a per-bp filter on the partner sort.

Same static-heap drain-burst as greedy: pop the node with the most missing stubs, sort the candidate set by id-ascending, take the first min(deficit, |candidates|). The filter strips any partner whose bp (B_u, B_n) has zero remaining budget; on accept, the bp counter goes down. When the bp pool runs dry early in the burst, the remainder of the deficit drops silently (canonical greedy's silent gridlock).

def cluster_preserving_greedy(residual, adj, b, bp_budget): heap = max-heap of (residual[u], u) for u with residual[u] > 0 while heap not empty: u = heap.pop() candidates = sorted({v : v != u, v not in adj[u], residual[v] > 0}) candidates = [v for v in candidates if bp_budget[bp(b[u], b[v])] > 0] for v in candidates[:residual[u]]: adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1 bp_budget[bp(b[u], b[v])] -= 1

algorithm · cluster_preserving_true_greedy

True-greedy, only partners whose bp still has budget.

Mirrors true_greedy: pop the highest-residual node and pick the single partner with maximum live degree, id-ascending tiebreak. The filter strips out-of-budget partners; on accept the bp counter goes down. Re-pushes both nodes into the heap with their decremented residuals. Gridlock (no in-budget partner with deficit left) is logged.

def cluster_preserving_true_greedy(residual, adj, b, bp_budget): heap = max-heap on residual while heap not empty: u = pop with re-push protocol (lazy delete) valid = [v for v in residual if v != u, v not in adj[u], bp_budget[bp(b[u], b[v])] > 0] if not valid: log.warn(...) v = max(valid, key=lambda x: (residual[x], -x)) accept (u, v); decrement bp_budget

algorithm · cluster_preserving_rewire

Per-bp stub-pair sampler + bp-preserving 2-opt.

Mirrors rewire's two-phase shape but works inside each bp independently. Phase 1: for every bp with a positive budget, draw stubs proportional to the per-node deficit restricted to that bp's blocks, shuffle, pair adjacent — exactly the residual-SBM stub draw gen_outlier uses on EC-SBM stage 3a. Self-loops and duplicates queue for repair. Phase 2 runs the same per-bp 2-opt swap as graph_utils.cluster_preserving_2opt_rewire: pick a random valid edge inside the bp, recombine endpoints with a coin flip when intra-block, swap "across" the bp partition when inter-block. Up to ten retries; whatever still conflicts at the end is dropped.

The page walker is algorithmically faithful to the canonical Python but does not byte-equal it: canonical delegates the stub draw to gt.generate_sbm, whose RNG is not portable to JS. The page kernel uses a JS-native weighted draw with the same control flow.

the --remap option

Pair by degree rank for gens that emit fresh node IDs.

Three of the simple gens (abcd, abcd+o, lfr) and nPSO emit integer node IDs that have no relation to the input's IDs: ABCD's com.tsv uses 1, 2, ..., N, LFR's binary outputs 0, 1, ..., N-1, and nPSO's MATLAB sampler labels nodes by arrival rank. Naively diffing degrees against the input's IDs is meaningless. The --remap flag pairs nodes by degree rank: the input node at rank \(i\) (descending input-degree) is paired with the output node at rank \(i\) (descending output-degree), and the deficit is computed on that pairing.

Algorithm-side this is an accounting layer: the matcher still adds edges in the input's ID space, but it judges deficits against the rank-paired target. The pairing is the L1- and L2-optimal one (rearrangement inequality) for matching two non-identical degree sequences. There is no on-disk re-ID; the output edge.csv keeps the input's IDs throughout.

when to use --remap

Whenever the gen's stage-2 output uses fresh integer IDs that you want to align to the input's degree sequence post-hoc. The simple-gen wrappers turn it on by default whenever they enable --match-degree; the SBM family does not need it because their gens already emit edges in the input's ID space.
