network-generation · shared utility

match_degree

A top-up tool every generator can call after its main pass. Reads two edgelists (current graph + reference target), finds per-node residual deficits, and adds edges that close the gap.

Every generator in this project ends with an output that is "close to" the input degree sequence but not exact. Dedup, rewire, and outlier handling each shave a few stubs from each node's target. src/match_degree.py is the shared finishing tool: pop the highest-deficit node, find a partner with deficit and no edge between them, drop the edge in. Repeat until the deficit set is empty or every remaining pair is blocked.

That last word, "blocked", is where the algorithm choices matter. The same residual can be drained five different ways, and they disagree on which pairs to try, in what order, and what to do when a deficit cannot be closed cleanly. The choices show up as different output degree sequences and different counts of unplaced stubs.

input contract

Two edgelists in. Top-up edges out.

The CLI is generator-agnostic:

python src/match_degree.py \ --input-edgelist <current.csv> \ --ref-edgelist <target.csv> \ --match-degree-algorithm greedy|true_greedy|random_greedy|rewire|hybrid \ --output-folder <dir> \ --seed <int> \ [--remap]

The two inputs share a node set. For each node \(u\), the residual deficit is

\[ r_u \;=\; \max\bigl(0, \,d_u^{\text{ref}} - d_u^{\text{input}}\bigr), \]

where \(d_u^{\text{ref}}\) is \(u\)'s degree in the reference and \(d_u^{\text{input}}\) is its degree in the current graph. The matcher's job is to add new edges so that, post-match, \(d_u^{\text{out}} \approx d_u^{\text{ref}}\) for every \(u\). It can never reduce a degree; if some node already has more edges than its target, it is left alone.

when each generator calls it

EC-SBM-v1 hardcodes greedy (legacy from the original paper implementation). EC-SBM-v2 defaults to hybrid. The simple gens (sbm, abcd, abcd+o, lfr, npso) leave it off by default; their pipelines accept --match-degree as an opt-in flag, paired with the optional --remap mode below for gens that emit fresh node IDs.

the five algorithms · overview

Different ways to drain the same deficit pile.

All five algorithms share the same outer loop: pick a node \(u\) with positive deficit, pick a partner \(v\) such that \((u, v)\) is not already an edge and \(v\) has positive deficit, add the edge, decrement both. They differ on the picking order and on what they do when the loop stalls.

algorithmhow it picks pairsfailure mode
greedy Heap-based. Pop \(u\) with max residual; connect to min(residual, |non-neighbours|) partners drawn via set.pop(). Silent gridlock: drops stubs without logging.
true_greedy Max-heap with dynamic re-push. Pop \(u\), pick \(v\) via argmax over current degrees among valid targets, push updated residuals back. Logs gridlock when no partner is left.
random_greedy Weighted-random \(u\) (by residual), weighted-random \(v\) from valid targets. Logs gridlock; useful for comparing bias against deterministic greedy.
rewire Configuration-model pairing then 2-opt repair. Build a flat stub list (each node repeated residual times), shuffle, pair adjacent. Invalid pairs queue for run_rewire_attempts. Logs gridlock; almost always resolves on realistic inputs.
hybrid (default) Run rewire first, then true_greedy on whatever rewire could not place. Rewire handles the bulk unbiased; greedy handles the stuck tail deterministically. Logs gridlock; drops near zero on realistic inputs.

Greedy and true_greedy are deterministic given a seed; random_greedy and rewire are stochastic; hybrid is a deterministic-then-stochastic composition. algorithm · greedy

Heap pop, partner via set.pop().

v1's matcher. Pops the node with the most missing stubs and drains it via Python's set.pop(). The Python docs claim set.pop() returns "an arbitrary element", but for sets of small integers the implementation is effectively deterministic: hash(n) == n, the underlying hash table iterates in slot order, and small ints hash to their own slot. The end result is that greedy drains candidates roughly in id-ascending order, not randomly. The naming hides the determinism; the algorithm is more "id-sorted greedy" than "random greedy". Once \(u\)'s deficit is zero or partners run out, move on; unplaced stubs disappear without a log line.

def greedy(residual, adj): heap = max-heap of (residual[u], u) for u with residual[u] > 0 while heap not empty: u = heap.pop() candidates = {v : v != u, v not in adj[u], residual[v] > 0} while residual[u] > 0 and candidates: v = candidates.pop() # int hash table → id-ascending in practice adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1 # residual[u] > 0 here means u was starved. dropped silently.

caveat: silent gridlock

If a node is starved (no valid partner with deficit), greedy drops the remaining stubs without logging. The achieved degree drifts below the target, and downstream tools cannot tell whether a node "really" lost edges or just got starved by the matcher. The four other algorithms below all log gridlock as a WARN.

algorithm · true_greedy

Heap pop, partner via argmax over current degrees.

Same outer pop as greedy, but the partner pick is deterministic: among valid targets (node not yet adjacent, has positive deficit), pick the one with the highest current achieved degree. Tie-break by id ascending. After each pair, push updated residuals back into the heap so subsequent pops see fresh values.

def true_greedy(residual, adj, deg): heap = max-heap of (residual[u], u) for u with residual[u] > 0 while heap not empty: u = heap.pop() while residual[u] > 0: valid = {v : v != u, v not in adj[u], residual[v] > 0} if not valid: break v = argmax(valid, key=lambda v: deg[v]) # id-asc tiebreak adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1 deg[u] += 1; deg[v] += 1 heap.push(residual[v], v) if residual[u] > 0: log.warn(f"gridlock at u={u}, {residual[u]} stubs unplaced")

Picking by max current degree biases toward already-popular nodes, which is fine for top-up because those are the ones with the most candidate partners. The deterministic tiebreak and explicit gridlock log are the two changes from greedy.

algorithm · random_greedy

Weighted-random pop, weighted-random partner.

Both picks are randomised. \(u\) is drawn proportional to its current residual; \(v\) is drawn uniformly from the valid set. Useful when comparing matcher bias against the deterministic algorithms: the same input run with several seeds reveals how much of the output depends on which deterministic ordering greedy and true_greedy lock in.

def random_greedy(residual, adj, rng): while any(residual[u] > 0): u = rng.choice(nodes, weights=residual) # residual-weighted valid = {v : v != u, v not in adj[u], residual[v] > 0} if not valid: log.warn(f"gridlock at u={u}, {residual[u]} stubs unplaced") residual[u] = 0 # abandon this node continue v = rng.choice(valid) # uniform among valid targets adj[u].add(v); adj[v].add(u) residual[u] -= 1; residual[v] -= 1

Each random click reseeds and reruns the algorithm; step through to see how the picks differ across seeds. Step counts vary because gridlock-and-abandon makes the algorithm length depend on which u happens to get starved.

algorithm · rewire

Configuration-model pairing, then 2-opt repair on invalid pairs.

The unbiased one. Build a flat stub list (each node \(u\) appears residual[u] times), shuffle, pair adjacent entries. Some pairs are invalid (self-loop, already an edge, or duplicate within this pairing). Queue them, then run a 2-opt swap pass that repairs each invalid pair against a random valid edge in the queue. Stagnation detector after a fixed retry budget.

def rewire(residual, adj, rng): stubs = [u for u in nodes for _ in range(residual[u])] rng.shuffle(stubs) pairs, invalid = [], [] for i in range(0, len(stubs), 2): u, v = stubs[i], stubs[i + 1] if u == v or v in adj[u]: invalid.append((u, v)) else: pairs.append((u, v)) adj[u].add(v); adj[v].add(u) # 2-opt repair phase for attempt in range(MAX_RETRIES): if not invalid: break u, v = invalid.pop() x, y = rng.choice(pairs) # try swapping with valid edge (x, y) if can_swap(u, v, x, y, adj): adj[u].add(y); adj[y].add(u) adj[x].add(v); adj[v].add(x) adj[x].discard(y); adj[y].discard(x) pairs.remove((x, y)); pairs.extend([(u, y), (x, v)]) else: invalid.append((u, v)) # requeue if invalid: log.warn(f"rewire: {len(invalid)} pairs unresolved after {MAX_RETRIES}")

The shuffle is the source of variation across seeds. On dense inputs almost every pairing is valid on the first pass; the repair queue is short. On long-tailed inputs with hubs, several pairs land invalid (the same hub gets two stubs that pair together); the repair phase walks them.

algorithm · hybrid (default)

rewire, then true_greedy on what is left.

The default and the recommended one. Run rewire first to drain the bulk unbiased; whatever stubs are still unplaced after rewire's repair budget go to true_greedy for a deterministic finishing pass. Almost every realistic deficit drains to zero this way; what cannot is logged.

def hybrid(residual, adj, rng): rewire(residual, adj, rng) # phase 1: stochastic bulk drain if any(residual[u] > 0): true_greedy(residual, adj, deg) # phase 2: deterministic tail if any(residual[u] > 0): log.warn(f"hybrid: {sum(residual)} stubs unplaced after both phases")

the --remap option

For gens that emit fresh node IDs, pair by degree rank instead of by ID.

Three of the simple gens (abcd, abcd+o, lfr) and nPSO emit integer node IDs that have no relation to the input's IDs: ABCD's com.tsv uses 1, 2, ..., N, LFR's binary outputs 0, 1, ..., N-1, and nPSO's MATLAB sampler labels nodes by arrival rank. Naively diffing degrees against the input's IDs is meaningless. The --remap flag pairs input node \(i\) (sorted by descending input-degree) with output node \(\pi(i)\) (sorted by descending output-degree), then computes the deficit on that pairing.

Algorithm-side this is just an accounting layer: the matcher still adds edges in the input's ID space, but it judges deficits against the rank-paired target. The pairing is the L1- and L2-optimal one (rearrangement inequality) for matching two non-identical degree sequences. There is no on-disk re-ID; the output edge.csv keeps the input's IDs throughout.

when to use --remap

Whenever the gen's stage-2 output uses fresh integer IDs that you want to align to the input's degree sequence post-hoc. The simple-gen wrappers turn it on by default whenever they enable --match-degree; the SBM family does not need it because their gens already emit edges in the input's ID space.
