match_degree

A top-up tool every generator can call after its main pass. Reads two edgelists (current graph + reference target), finds per-node residual deficits, and adds edges that close the gap.

Every generator in this project ends with an output that is "close to" the input degree sequence but not exact. Dedup, rewire, and outlier handling each shave a few stubs from each node's target. src/match_degree.py is the shared finishing tool: pop the highest-deficit node, find a partner with deficit and no edge between them, drop the edge in. Repeat until the deficit set is empty or every remaining pair is blocked.

That last word, "blocked", is where the algorithm choices matter. The same residual can be drained five different ways, and they disagree on which pairs to try, in what order, and what to do when a deficit cannot be closed cleanly. The choices show up as different output degree sequences and different counts of unplaced stubs.

input contract

Two edgelists in. Top-up edges out.

The CLI is generator-agnostic:

python src/match_degree.py \\
  --input-edgelist <current.csv> \\
  --ref-edgelist <target.csv> \\
  --match-degree-algorithm greedy|true_greedy|random_greedy|rewire|hybrid \\
  --output-folder <dir> \\
  --seed <int> \\
  [--remap]

The two inputs share a node set. For each node \(u\), the residual deficit is

\[ r_u \;=\; \max\bigl(0, \,d_u^{\text{ref}} - d_u^{\text{input}}\bigr), \]

where \(d_u^{\text{ref}}\) is \(u\)'s degree in the reference and \(d_u^{\text{input}}\) is its degree in the current graph. The matcher's job is to add new edges so that, post-match, \(d_u^{\text{out}} \approx d_u^{\text{ref}}\) for every \(u\). It can never reduce a degree; if some node already has more edges than its target, it is left alone.

when each generator calls it

EC-SBM-v1 hardcodes greedy (legacy from the original paper implementation). EC-SBM-v2 defaults to hybrid. The simple gens (sbm, abcd, abcd+o, lfr, npso) leave it off by default; their pipelines accept --match-degree as an opt-in flag, paired with the optional --remap mode below for gens that emit fresh node IDs.

the five algorithms

Different ways to drain the same deficit pile.

All five algorithms share the same outer loop: pick a node \(u\) with positive deficit, pick a partner \(v\) such that \((u, v)\) is not already an edge and \(v\) has positive deficit, add the edge, decrement both. They differ on the picking order and on what they do when the loop stalls.

algorithmhow it picks pairsfailure mode
greedy Heap-based. Pop \(u\) with max residual; connect to min(residual, |non-neighbours|) partners drawn via set.pop(). Silent gridlock: drops stubs without logging.
true_greedy Max-heap with dynamic re-push. Pop \(u\), pick \(v\) via argmax over current degrees among valid targets, push updated residuals back. Logs gridlock when no partner is left.
random_greedy Weighted-random \(u\) (by residual), weighted-random \(v\) from valid targets. Logs gridlock; useful for comparing bias against deterministic greedy.
rewire Configuration-model pairing then 2-opt repair. Build a flat stub list (each node repeated residual times), shuffle, pair adjacent. Invalid pairs queue for run_rewire_attempts. Logs gridlock; almost always resolves on realistic inputs.
hybrid (default) Run rewire first, then true_greedy on whatever rewire could not place. Rewire handles the bulk unbiased; greedy handles the stuck tail deterministically. Logs gridlock; drops near zero on realistic inputs.

Greedy and true_greedy are deterministic given a seed; random_greedy and rewire are stochastic; hybrid is a deterministic-then-stochastic composition. On dense inputs all five converge; on long-tail-degree inputs with hubs, greedy is the one that silently drops stubs, true_greedy is the one that gridlocks loudly, and hybrid is the one that drains the tail without bias.

caveat: silent gridlock in greedy

A node with residual 3 and only one valid partner leaves the heap with residual 2. Those two stubs vanish without a log line. On a small synthetic you rarely see this. On dense inputs with long-tailed degree distributions, a handful of hubs silently come out short, and the degree-sequence target starts drifting below the profile's. true_greedy, rewire, and hybrid all log the same situation as a WARN with the count of unplaced stubs.

the --remap option

For gens that emit fresh node IDs, pair by degree rank instead of by ID.

Three of the simple gens (abcd, abcd+o, lfr) and nPSO emit integer node IDs that have no relation to the input's IDs: ABCD's com.tsv uses 1, 2, ..., N, LFR's binary outputs 0, 1, ..., N-1, and nPSO's MATLAB sampler labels nodes by arrival rank. Naively diffing degrees against the input's IDs is meaningless. The --remap flag pairs input node \(i\) (sorted by descending input-degree) with output node \(\pi(i)\) (sorted by descending output-degree), then computes the deficit on that pairing.

Algorithm-side this is just an accounting layer: the matcher still adds edges in the input's ID space, but it judges deficits against the rank-paired target. The pairing is the L1- and L2-optimal one (rearrangement inequality) for matching two non-identical degree sequences. There is no on-disk re-ID; the output edge.csv keeps the input's IDs throughout.

when to use --remap

Whenever the gen's stage-2 output uses fresh integer IDs that you want to align to the input's degree sequence post-hoc. The simple-gen wrappers turn it on by default whenever they enable --match-degree; the SBM family does not need it because their gens already emit edges in the input's ID space.
