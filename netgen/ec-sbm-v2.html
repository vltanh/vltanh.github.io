netgen · ec-sbm-v2

EC-SBM v2

Same $$k$$-edge-connectivity guarantee as v1, with cleaner residual accounting, one SBM call instead of two, and a block-preserving 2-opt rewire that keeps the degree sequence honest.

v1 runs four stages, two SBM calls, and silently drops a handful of residual stubs along the way. v2 is what you get if you stare at v1 for an afternoon and rewrite the parts that annoyed you.

Three changes. Stage 2 is constructive only, no SBM overlay on mutated probs. Stage 3 is a single residual SBM over all blocks (real clusters plus a combined outlier block), which subsumes what v1 needed two SBM calls to express. Stage 4 gains a block-preserving 2-opt rewire and a menu of five matcher algorithms, so the "silent drop" bug is gone.

stage 0 · the question

Can the degree sequence survive the block matrix?

v1's pain: stage 2 mutates the degree array and the block matrix while building the Kk+1 cores, then hands those mutated arrays to the SBM, which samples more edges on top, and then dedup drops some of the collisions. At every step an edge might be added and an edge might disappear, and keeping track of who owes what to whom is a mess.

v2's answer: keep the constructive part honest, then compute the residual exactly, then hand the residual (and only the residual) to the SBM.

stage 1 · cores (same as v1)

Build the k-edge-connected skeleton.

Identical to v1's stage 2 phase 1. Sort each cluster's nodes by degree. Top $$k+1$$ form a complete subgraph. Walk remaining nodes in degree-desc order and wire each to $$k$$ top-processed partners. If a budget would block a required edge, inflate the budget rather than drop it.

What v2 does not do: call gt.generate_sbm here. Stage 2 ends with just the constructive edges. The SBM is deferred to stage 3.

stage 2 output (constructive only) azure = stage 2
same guarantee, cleaner accounting

The $$K_{k+1}$$ core gives the same edge-connectivity proof as in v1. What differs is that this stage no longer runs two couples of books. Degrees get decremented, probs get decremented, nothing else.

stage 2 · residual accounting

Compute what the SBM still owes each block.

For each block $$k$$, let $$D_k$$ be the sum of residual degrees (target minus stage-2 contribution, clamped at 0) and $$E^{\text{inter}}_k$$ be the row-sum of the inter-block probs for row $$k$$. The intra-block budget the SBM still needs to place is

$$\text{diff} = D_k - E^{\text{inter}}_k$$

If $$\text{diff} \geq 0$$, set $$\texttt{probs}[k,k] = \text{diff}$$ (bump up by 1 for parity if odd). If $$\text{diff} < 0$$, stage 2 already over-spent the intra-budget; add $$|\text{diff}|$$ back to out_degs and set $$\texttt{probs}[k,k] = 0$$. Outliers fold into one combined extra block under the default --gen-outlier-mode combined.

every edge is owned by exactly one stage

Constructive edges belong to stage 2. Residual inter-block edges and the residual intra counts come from stage 3's SBM. Match-degree fills in whatever dedup or rewire removed. No double-accounting.

stage 3 · residual SBM + rewire

One SBM call, then a block-preserving 2-opt rewire.

The residual SBM can still emit self-loops and parallel edges. v1 just dedupped them and accepted the degree loss. v2 tries to rewire instead: for each invalid edge, pick a valid edge from the same block-pair bucket and swap endpoints so that each node stays in its home block. The degrees are preserved; the block-pair edge counts are preserved; the collision is gone.

step 0 · an invalid edge step 0 / 3
the invariant of the swap

If the invalid edge $$(u, v)$$ has block-pair $$(A, B)$$ with $$A \neq B$$, the partner edge $$(x, y)$$ must also sit in bucket $$(A, B)$$. The swap pairs the A-side of each edge with the B-side of the other: $$(u_A, x_B)$$ and $$(x_A, u_B)$$. Both nodes stay in their home block, so the block matrix counts are invariant.

stage 4 · hybrid matcher

Rewire phase first, then a true-greedy pass on whatever remains.

After the residual SBM + rewire, some nodes are still short of their target degree. v1 runs a heap-greedy that silently drops stubs when a node's non-neighbor set runs out. v2's default is --algorithm hybrid: build a configuration-model stub pairing, rewire any invalid pairs (same 2-opt as stage 3), then hand the survivors to a dynamic true-greedy heap.

Rewire handles the bulk unbiased; true-greedy handles the stuck tail deterministically. Net effect: nearly zero silent drops on realistic inputs.

five matchers, one default

greedy (v1's), true_greedy (dynamic re-push), random_greedy (weighted random), rewire (config-model + 2-opt), hybrid (rewire then true-greedy). The registry ships true_greedy; I would reach for hybrid.
