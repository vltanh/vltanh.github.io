network-generation · ec-sbm-v2

EC-SBM v2

Same per-cluster \(k\)-edge-connectivity floor as v1. One SBM call on a proper residual (no overlay), a block-preserving 2-opt rewire, and a hybrid degree matcher that logs gridlock instead of dropping stubs.

v1 gets the right cluster guarantees, but the bookkeeping is messy. Stage 2 builds \(K_{k+1}\) cores and runs an SBM on the decremented probs + degree arrays; the SBM can sample a pair the core already placed, dedup drops one, and the block's intra-count leaks below the profile. Stage 3 handles outliers through a separate SBM, and stage 4 runs a heap-greedy matcher that silently drops stubs when a hub runs out of valid partners.

v2 keeps the \(K_{k+1}\) cores and rebuilds the rest. Stage 2 is constructive-only; nothing else samples during the core phase. Stage 3 is a single residual SBM over every block (real clusters plus a combined outlier block), with invalid edges fed to a block-preserving 2-opt rewire that preserves both the block-pair counts and each node's block membership. Stage 4 offers five matcher algorithms, with a hybrid (rewire + true-greedy) default that logs gridlock rather than hiding it.

Every edge is owned by exactly one stage, and nothing disappears without a log line. The per-cluster edge-connectivity proof is inherited verbatim from v1.

The profile stage is identical to v1: the five SBM tables plus mincut.csv, and outlier_mode=excluded drops unclustered nodes along with their incident edges. The outliers come back in stage 3 as a single combined block (v2's default --gen-outlier-mode combined), not one block per node the way v1's stage 3a treats them.

why combined, not singleton

A size-1 cluster has no internal edges (no partner inside), so giving each outlier its own block adds rows and columns to the block matrix without filling any diagonal. Under combined, every outlier shares one block; the outlier-outlier diagonal cell captures the real edges they have among themselves; clustered-outlier cells capture the cross edges. One block means one residual-SBM cell per relation, which is all v2's stage 3 needs.

generation · the \(K_{k+1}\) core (unchanged from v1)

Clique on top \((k+1)\) nodes, attach the rest, decrement the budgets.

Same Python as v1's core phase: sort cluster nodes by degree desc, wire the top \(k+1\) into a complete subgraph, walk the remaining nodes in degree-desc order and attach each to \(k\) top-processed partners. ensure_edge_capacity inflates when a required edge would be blocked. The one change: stage 2 stops here. No gt.generate_sbm call, no overlay.

same proof, cleaner ledger

Per-cluster edge-connectivity \(\ge k(C)\) is still guaranteed by the \(K_{k+1}\) seed. What changes is that probs and deg are decremented by exactly the constructive contribution and nothing else; the residual that the SBM sees next is honest.

generation · residual accounting

Compute what the SBM still owes each block.

Before the SBM call, prepare_sbm_inputs rewrites the intra-block diagonal so the residual adds up. For each block \(k\) (the three real clusters plus the combined outlier block):

\[ D_k \;=\; \max\!\left(0, \; \sum_{u \,:\, b_u = k} \bigl(k^{\text{target}}_u - k^{\text{stage2}}_u\bigr)\right), \quad E^{\text{inter}}_k \;=\; \sum_{s \neq k} \texttt{probs}[k, s]. \]

Read \(D_k\) as "residual half-edges block \(k\) still owes" and \(E^{\text{inter}}_k\) as "inter-block half-edges block \(k\) is already committed to". The intra-block cell the SBM still needs to sample is

\[ \text{diff}_k \;=\; D_k \;-\; E^{\text{inter}}_k. \]

If \(\text{diff}_k \ge 0\), set \(\texttt{probs}[k, k] = \text{diff}_k\) (bump by 1 if it is odd, to satisfy graph-tool's even-half-edges-per-block parity rule). If \(\text{diff}_k < 0\), the core already over-spent the block's budget; add \(|\text{diff}_k|\) back to out_degs and set \(\texttt{probs}[k, k] = 0\) (the SBM can only add, never subtract).

every edge owned by one stage

Constructive edges belong to stage 2. Residual intra and inter come from stage 3's SBM. Match-degree covers whatever the rewire drops. No cell is "sampled twice", and nothing is "double-counted" because probs has already been decremented by what stage 2 placed.

generation · SBM + block-preserving 2-opt rewire

One SBM call, then swap endpoints to kill invalid edges.

With the residual probs and the combined-outlier block assignment ready, v2 calls gt.generate_sbm(b, probs, out_degs, micro_ers=True, micro_degs=True) once. The sampler can still emit self-loops (two of the block's stubs landing on the same node) and parallel edges (two stubs for the same pair pairing up twice). v1 dedupped them and accepted the degree loss. v2 tries to fix each one via a 2-opt swap.

The swap: bucket every valid edge by its unordered block-pair \((A, B)\); for each invalid edge, pick a random valid edge in the same bucket and swap endpoints so each node stays in its home block. That preserves both the block-pair count and every node's block membership. Up to 10 retry passes with a stagnation detector. Unresolved invalids are dropped with a WARN.

step 0 · residual edges sampled step 0 / 3
invariant of the swap

If the invalid edge \((u, v)\) has block-pair \((A, B)\) with \(A \neq B\), the partner edge \((x, y)\) must also sit in bucket \((A, B)\). Swap the \(A\)-side of each edge with the \(B\)-side of the other: \((u_A, x_B)\) and \((x_A, u_B)\). Both nodes stay in their home block, so the block-pair count is invariant. For intra-block \((A = A)\) there are two valid swaps; the code flips a coin.

generation · match degree, with choices

Five matchers, one default.

After the residual SBM + rewire, some nodes are still short of their target. v2's src/match_degree.py ships five algorithms, selectable via --algorithm:

algorithmhow it picks pairsfailure mode
greedy v1's heap-based. Pop \(u\) with max residual, connect to min(residual, non-neighbours) partners via set.pop(). Silent gridlock.
true_greedy Max-heap with dynamic re-push. Pop \(u\), pick \(v\) via argmax over current degrees among valid targets, push updated residuals back. Logs gridlock.
random_greedy Weighted-random \(u\) (by residual), weighted-random \(v\) from valid targets. Logs gridlock, useful for comparing bias against deterministic greedy.
rewire Configuration-model pairing then 2-opt repair. Build a flat stub list (each node repeated residual times), shuffle, pair adjacent. Invalid pairs queue for the same run_rewire_attempts used in stage 3. Logs gridlock.
hybrid (default) Run rewire first, then true_greedy on whatever rewire could not place. Rewire handles the bulk unbiased; greedy handles the stuck tail deterministically. Logs gridlock; drops near zero on realistic inputs.

why v2's global cc beats v1's on this input

Both versions place the same \(K_{k+1}\) cores. v1 then runs an SBM on the mutated probs and uses remove_parallel_edges for collisions; the sampler can land on core pairs, dedup drops one side, and the intra-block density (and therefore the local clustering inside that block) is shaved. v2's rewire keeps the block-pair count intact, so the core cliques' triangle structure stays in place and the global cc sits closer to the input's 0.548.

caveat: rewire can still strand a handful of edges

Rewire is not a complete repair. When no valid partner sits in the same bucket, an invalid edge stays invalid; after 10 retry passes or a stagnation break, those unresolved edges are dropped with a WARN. On dnc at this seed the total drop is tens of edges out of ten thousand, invisible in the stats table but present in run.log. For a matcher algorithm that refuses to drop, --algorithm rewire on stage 4 is still lossy in the same way (if rewire cannot resolve, true_greedy takes over under hybrid; in plain rewire mode the same stub vanishes).
