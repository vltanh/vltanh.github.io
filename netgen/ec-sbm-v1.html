EC-SBM v1

SBM with an edge-connectivity guarantee. Each output cluster is at least as edge-connected as its input counterpart, delivered by stitching a hand-built $$k$$-edge-connected core into each cluster before sampling.

Plain SBM has a quiet flaw. It will happily produce a cluster that is technically connected but one snip away from breaking apart. For work on robustness or min-cut attacks, that is a deal-breaker.

EC-SBM adds a promise: the output cluster's edge-connectivity is at least as high as the input's. The way it delivers that promise is blunt: before the SBM runs, hand-build a dense skeleton in each cluster that is guaranteed $$k$$-edge-connected, then let the sampler fill in everything else on top.

This is v1, the first cut. It runs four stages, uses two separate SBM calls, and drops a few residual stubs silently. v2 is the cleanup.

stage 0 · the question

How many edges would you have to remove to break this cluster?

Pick a cluster $$C$$ in the input. Count the minimum number of edges you would need to remove from $$C$$'s induced subgraph to disconnect it. Call that number $$k(C)$$, the mincut.

In our synthetic, C1 has $$k=3$$, C2 has $$k=2$$, C3 has $$k=1$$. The promise we want: whatever SBM emits for cluster $$C$$, its mincut must be at least $$k(C)$$.

v1 forces outlier mode excluded: outliers 19 and 20 are dropped along with all their edges before the clustered pass runs. They will come back later (stage 3) through a separate SBM. The clustered pass sees only the three real clusters.

the mincuts are the target

Computed at profile time via the Nagamochi-Ibaraki algorithm on each cluster's induced subgraph. Singleton clusters get $$k=0$$ by definition.

stage 2 · the k+1 clique

Build a $$K_{k+1}$$ core in every cluster, vertex by vertex.

Sort each cluster's nodes by degree, descending. Take the top $$k+1$$ and wire them into a complete subgraph. That is $$\binom{k+1}{2}$$ edges. The theorem: a complete graph on $$k+1$$ vertices is $$k$$-edge-connected. So every cluster that contains this clique is automatically at least $$k$$-edge-connected, regardless of what happens after.

Then the rest of the cluster attaches vertex by vertex. Each new vertex wires to the $$k$$ top-degree already-processed nodes. When a required edge's budget is exhausted, the code inflates the budget rather than drop the edge. That is the knob that makes the degree sequence approximate rather than exact.

why this works

$$K_{k+1}$$ is the tightest k-edge-connected subgraph you can write down. Adding more vertices and edges on top can only increase connectivity, never decrease it. The construction bakes the guarantee in as a structural invariant.

stage 3 · sbm overlay

Let the sampler fill in the residual on the mutated probs.

After the constructive phase, the block matrix and the degree sequence have been mutated: decremented each time an edge was applied, inflated when ensure_edge_capacity fired. Stage 2 of v1 then calls gt.generate_sbm on those mutated arrays, overlays the constructive edges on top, and simplifies.

If an SBM-sampled edge lands on the same pair as a constructive edge, remove_parallel_edges drops one. This double-accounting is the reason v2 was written: it is cleaner to let one SBM call do all the sampling on a proper residual.

stage 4 · outlier rescue

Bring the outliers back through a separate SBM.

Because v1 forced outlier mode excluded, the clustered SBM never saw nodes 19 and 20. Stage 3a re-reads the original edgelist, identifies outliers as nodes present in the edgelist but absent from the clustering, and samples an SBM on just the outlier-incident edges. Each outlier is its own size-1 block.

The result is combined with stage-2 output via an undirected dedup, first-seen-wins. Stage-2 edges take priority over stage-3 on any collision.

stage 2 + stage 3a (outlier SBM) orchid = stage 3
stage 5 · match degree

Top up the residual degree deficit.

After the dedup in stage 2 and the outlier pass in stage 3, some nodes are still short of their target degree from the input. Stage 4a tops them off with a heap-based greedy: pop the node with the largest residual, connect it to up to min(residual, non-neighbors) partners, decrement both sides.

If a node runs out of valid partners before its residual hits zero, the remaining stubs are silently dropped. v1 does not log this. v2 does, and gives you a choice of five matcher algorithms.

the silent drop

A node with residual 3 and only one valid partner exits the heap with residual 2. Those two stubs vanish. On small graphs the effect is invisible; on dense graphs with heavy tails, gridlock accumulates. v2's --algorithm hybrid (rewire + true-greedy fallback) pushes this near zero.
