network-generation · ec-sbm-v1

EC-SBM v1

SBM with a per-cluster edge-connectivity floor. Hand-builds a \(K_{k+1}\) core inside every cluster so the output cluster survives any \(k-1\) edge removals, then layers an SBM sample on top of what the cores already spent.

Plain SBM freezes three things about the input: each node's block label, each node's degree, and the per-pair edge count matrix. Triangles are not in that contract, and neither is edge-connectivity. A cluster can come out "connected" but one snip away from falling in half: the sampler is free to place intra-block edges on a handful of pairs while starving the rest.

EC-SBM adds a fourth quantity. Measure the min-cut \(k(C)\) of each cluster \(C\) in the input and promise that every output cluster is at least that edge-connected. Before any SBM sampling, hand-build a \(K_{k(C)+1}\) clique inside \(C\) using the top-degree nodes; every later edge can only raise connectivity, never drop it below \(k(C)\).

This is v1, the first cut. Four stages, two separate SBM calls, one pass of silent stubs dropped in the degree matcher. v2 is the rewrite: cleaner residual accounting, a single SBM call, and a matcher that logs instead of drops.

profiling · add a min-cut to the contract

One new scalar per cluster: \(k(C)\).

v1's profile stage writes the same five tables as plain SBM (node and cluster dictionaries, block assignment, degree sequence, block matrix) plus a sixth one: mincut.csv with one integer per cluster. For each cluster \(C\), \(k(C)\) is the minimum number of edges you would have to remove from \(C\)'s induced subgraph to disconnect it. Measured via pymincut's Nagamochi-Ibaraki algorithm ("noi" / "bqueue"). Singleton clusters get \(k = 0\) by definition.

v1 also forces outlier_mode=excluded at profile time: any node not in a size-2+ cluster, along with its incident edges, is dropped from the clustered inputs. Passing any other outlier mode is a hard error. The outliers come back in stage 3a through a separate SBM call.

the mincut is the only new piece

Assignment, degree, and block-counts are SBM's contract. EC-SBM reuses all three and adds \(k(C)\). Everything downstream exists to honour that one number.

generation · the \(K_{k+1}\) core

Complete subgraph on the top \(k+1\) nodes, then attach the rest.

Per cluster \(C\), sort nodes by degree desc. Take the top \(k+1\), wire them into a complete subgraph \(K_{k+1}\): that is \(\binom{k+1}{2}\) edges. The well-known fact: a complete graph on \(k+1\) vertices is \(k\)-edge-connected. So every cluster that contains these \(k+1\) nodes as a clique is \(k\)-edge-connected, regardless of what the SBM layer places on top.

Phase 2 walks the remaining cluster nodes in degree-desc order. Each new node \(u\) attaches to up to \(k\) of the already-processed nodes, preferring high-degree partners; when the first loop runs out of candidates, a numpy-weighted random choice (weights = input profile degree) fills the gap. When the partner's residual degree or the block-pair budget would block a required edge, ensure_edge_capacity inflates them so the edge can go in:

\[ \texttt{int\_deg}[v] \mathrel{+}= 1, \quad \texttt{probs}[b_u, b_v] \mathrel{+}= 1. \]

Inflation is the only reason the output's degree sequence ends up approximate. Walk through the construction below.

why \(K_{k+1}\) is the tightest seed

A complete graph on \(k+1\) vertices has \(\binom{k+1}{2}\) edges, exactly \(k\) per vertex, and is \(k\)-edge-connected. Any smaller complete graph is not enough; any bigger one spends edges the profile would rather place elsewhere. v1 inflates budget to protect the seed edges, not to shrink them.

generation · SBM overlay on the mutated residual

One SBM call on what is left, then overlay the cores and drop collisions.

After the constructive pass, the block matrix and the degree array have been decremented for every edge the core phase placed and inflated wherever the budget was too tight. v1 feeds those mutated arrays to gt.generate_sbm(micro_ers=True, micro_degs=True), producing a fresh sample that should fill the "residual" the core phase did not spend. Then it overlays the constructive edges and simplifies:

g = gt.generate_sbm(b, probs.tocsr(), out_degs=deg, ...)
g.add_edge_list(core_edges)
gt.remove_parallel_edges(g); gt.remove_self_loops(g)

The catch is in the ordering. The SBM call does not know about the constructive edges: it draws stubs against whatever it finds in the mutated arrays, which can land on the same pair the core already claimed. The remove_parallel_edges step then collapses both copies to one, and that intra-block half-edge count drops by two below what the profile asked for. This is the central reason v2 was written. Toggle the overlay to watch it happen on the synthetic.

caveat: the double-accounting

Two samplers writing into the same ledger. The constructive phase commits edges, decrements budget. The SBM phase redraws on the decremented budget but can still sample the same pair the core already placed; dedup drops one. Net per collision: budget charged twice, edge kept once, block's intra count lands under profile. v2 replaces this with a single residual-SBM call and a block-preserving 2-opt rewire that swaps endpoints instead of dropping edges.

generation · the outlier rescue

Outliers get their own SBM pass.

Stage 2 never saw outliers because the profile excluded them. Stage 3a re-reads the original (pre-exclusion) edgelist, flags every node that is in the edgelist but not in the clustering, and treats each outlier as a size-1 block of its own. It then samples an SBM on the outlier-incident edges only, so clustered-side pairs are not re-sampled.

The combine_edgelists.py merge is first-seen wins with stage 2 as input 1: if stage 3a emits a pair that stage 2 already placed, the stage-2 copy is kept and the provenance is fixed as clustered. Two pure bands, undirected-deduped, written to a fresh edge.csv plus sources.json mapping each band to an inclusive 1-based row range.

core + overlay + outlier rescue orchid = outlier SBM band
singleton outlier blocks emit edges, not structure

Each outlier is its own 1-node block, so the SBM only has inter-block cells to populate. Outlier-outlier edges come out as a single cell between two singletons; clustered-outlier edges come out as cells between a real cluster and a singleton. Nothing ever lands on a diagonal. Fold the outliers into one combined block instead and you get v2's single-SBM picture.

generation · match the residual degree

Heap-greedy top-up, silent drop when a hub runs out of partners.

Dedup and stage-3a together shave some edges off each node's degree. The final stage tops the shortfall back up with src/match_degree.py --algorithm greedy (hardcoded in v1):

  1. Build a max-heap of (-residual, node_id) over nodes still short of their target.
  2. Pop \(u\). Compute \(u\)'s non-neighbours (live nodes minus \(u\) and its current neighbours).
  3. Pop partners via set.pop() until \(u\)'s residual hits zero or candidates run out. Each pair becomes an edge; decrement both sides.
  4. If \(u\) ran out of partners first, the remaining stubs are silently dropped. No log line, no warning.

set.pop() picks an arbitrary element, so PYTHONHASHSEED=0 is load-bearing for reproducibility here. A second combine_edgelists.py merges stage 3b's edges with stage 4a's top-ups, accumulating match_degree as a third provenance band.

caveat: gridlock hides, the degree sequence leaks

A node with residual 3 and only one valid partner leaves the heap with residual 2. Those two stubs vanish without a log line. On a small synthetic you rarely see this. On dense inputs with long-tailed degree distributions, a handful of hubs silently come out short, and the degree-sequence target starts drifting below the profile's. v2's --algorithm hybrid (configuration-model pairing + block-preserving 2-opt rewire, then true-greedy fallback) drives this drop near zero and logs what it cannot place.

why the cc jumps against plain SBM

The \(K_{k+1}\) core on the 50-node cluster alone is \(K_{50}\): \(\binom{50}{2} = 1225\) intra-edges all packed on 50 nodes, forming a dense clique. Plain SBM on dnc lands at 0.341 global cc; v1 lands at 0.424. The delta is mostly those cliques. The \(K_{50}\) is a big chunk of dnc's total 10k edges, which is why the mincut distribution's long tail matters more than the count.

caveat: overlay dedup is invisible in the numbers

The dnc output misses the input edge count by 7 (10,422 vs 10,429) and the global cc by 0.124 (0.548 vs 0.424). How much of that shortfall is overlay-dedup and how much is match-degree gridlock? v1's logs do not say. v2's logs do, and they show overlay-dedup is the bigger share on dense inputs; gridlock is small when match-degree only has to fill a few stubs per hub.
