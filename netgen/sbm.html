network-generation · sbm

SBM

Degree-corrected stochastic block model. Freezes the block assignment, the per-pair edge counts, and the per-node degree sequence; the rest is random.

You have a real network. You want a synthetic twin that shares its block structure and its degree distribution but is otherwise drawn fresh. The stochastic block model says: a few things about \(G\) matter enough to freeze, and the rest is accident.

Peixoto's micro-canonical degree-corrected SBM freezes three things: (1) each node's block label, (2) the edge count between every pair of blocks \(e_{rs}\), and (3) each node's degree \(k_i\). Any graph that meets those three constraints is equally likely under the model.

The catch is honesty tax. Micro-SBM samples a multigraph where those constraints hit exactly, then a cleanup step drops self-loops and parallel edges so the output is a simple graph. On dense blocks the cleanup kills a visible fraction of edges, and the three frozen quantities end up as upper bounds, not targets hit.

stage 1 · profile

Three vectors, one matrix: that is the input contract.

Profile reads the reference network and its clustering and writes five CSVs. node_id.csv and cluster_id.csv are label dictionaries; assignment.csv, degree.csv, and edge_counts.csv hold the three quantities the sampler will try to match: per-node block, per-node degree, per-block-pair edge count.

Outlier handling happens here. Under the default outlier_mode=combined, every unclustered node and every size-1 cluster is folded into one pseudo-block labelled __outliers__, so the sampler never has to treat them as a separate case. The flag drop_outlier_outlier_edges is off by default, so outlier-outlier edges survive into the pseudo-block's diagonal.

stage 2 · the block matrix

Count edges per block-pair. That is the only structure the sampler sees.

For blocks \(r\) and \(s\), \(e_{rs}\) is the count of edges between any node in \(r\) and any node in \(s\). For \(r \neq s\), it is stored symmetrically: \(e_{rs} = e_{sr}\). For \(r = s\), graph-tool's undirected convention counts each intra-block edge twice (both half-edges land in the same block), so

\[ e_{rr} \;=\; 2 \cdot |\{(u, v) \in E : b(u) = b(v) = r\}|. \]

The matrix has one row and column per block, so on this synthetic it is a compact 4x4. Each edge in the graph contributes to exactly one cell (or to the pair \((r, s), (s, r)\) for inter-block edges). Click any edge to highlight the cell it lands in: the sampler will not remember which specific edge it was, only that the cell owes that many.

why this is the whole contract

Two graphs with the same \(e_{rs}\) matrix and the same degree sequence are equally likely under the degree-corrected SBM. The model cannot tell them apart and the sampler spreads probability across all such graphs uniformly. That is why SBM matches \(e_{rs}\) and \(k_i\) in distribution but reshuffles which specific pairs are connected: the specific pairs are not in the contract.

stage 3 · sample the multigraph

Stub-matching per block-pair, micro-canonical.

Each node \(i\) has a target degree \(k_i\) that splits across the blocks it connects to: call the split \(k_i^{(s)}\), the number of half-edges from \(i\) landing in block \(s\). The sums match the block matrix: \(\sum_{i \in r} k_i^{(s)} = e_{rs}\) for \(r \neq s\), and \(\sum_{i \in r} k_i^{(r)} = e_{rr} = 2 \cdot \text{intra-edges}(r)\).

For each block-pair \((r, s)\), build two stub lists (or one for \(r = s\)): each node \(i\) appears \(k_i^{(s)}\) times. Shuffle, pair up consecutively. Every pair becomes an edge; nothing is rejected.

the honest catch

The constraint is on counts, not distinct pairs. When a hub's stub lands next to one of its own other stubs (same block, \(r = s\)) the sampler emits a self-loop. When two of a hub's stubs for block \(s\) pair with two of another node's stubs for the same block, the sampler emits a parallel edge. Both are legal under the micro constraint. stage 4 · dedup

Collapse parallels, drop self-loops. Degree sequence stops being exact.

graph-tool's remove_parallel_edges + remove_self_loops run unconditionally at the end of gen.py. Each parallel edge between \((u, v)\) is collapsed to one; each self-loop on \(u\) is dropped. Every dropped half-edge is one unit of degree the sampler can no longer account for, so the output degree sequence sits at-or-below the target.

caveat 1: dedup loss is not uniform

The red heatmap above is the story. Parallels collide where stubs concentrate, so the loss clusters on the diagonal of dense blocks and on the outlier pseudo-block; most off-diagonal cells keep their edges. On dnc, the single largest cell alone loses 894 half-edges (out of 2,450) and the outlier block loses 108 of its 278 intra-edges. The degree sequence "we matched your hubs" is partly true pre-dedup and partly false post-dedup, and the discrepancy tracks block density.

caveat 2: global cc is not a target

The micro constraint pins \(e_{rs}\) and \(k_i\) but nothing about triangles. The stats table captures this: input cc 0.548, output cc 0.341. DC-SBM lands near the input cc when most of the input's triangles were degree-driven; on structured graphs like dnc where triangles sit inside dense communities, the sampler misses by a lot. If triangles matter, ec-sbm-v1 and ec-sbm-v2 add that level of structure on top.
