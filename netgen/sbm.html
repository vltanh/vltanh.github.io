network-generation · sbm

SBM

Degree-corrected stochastic block model. Freezes the block assignment, the per-pair edge counts, and the per-node degree sequence; the rest is random.

You have a real network, and its block (think "community") structure. You want a synthetic twin that keeps that block structure and the per-node degrees, and is otherwise drawn fresh. The stochastic block model says: a few things about \(G\) matter enough to freeze, and the rest is accident.

Peixoto's micro-canonical degree-corrected SBM freezes three things: (1) each node's block label, (2) the edge count between every pair of blocks \(e_{rs}\), and (3) each node's degree \(k_i\). Any graph that meets those three constraints is equally likely under the model.

The catch is dedup. Micro-SBM samples a multigraph where those constraints hit exactly, then a simplify step drops self-loops and parallel edges so the output is a simple graph. On dense blocks the simplify step kills a visible fraction of edges, and the three frozen quantities end up as upper bounds, not targets hit.

profiling · block assignment

Three vectors, one matrix: that is the input contract.

Profile reads the reference network and its clustering and writes five CSVs. Two are label dictionaries (node_id.csv, cluster_id.csv). The other three carry the quantities the sampler will try to match: assignment.csv (block per node, this section), degree.csv (degree per node, next), and edge_counts.csv (the edge count matrix, the section after). Anything not in those three vectors, like mean degree, triangle count, or pairwise distances, is not in the contract.

Write \(b\) for the block assignment (\(b_u \in \{1, \ldots, B\}\) for node \(u\)), \(k\) for the degree sequence (\(k_u\) = degree of \(u\)), and \(e\) for the block-pair count matrix (\(e_{rs}\) defined in the edge-count-matrix section below). The three sections that follow visualise \(b\), then \(k\), then \(e\), in that order.

Outlier handling happens here too. Under the default outlier_mode=combined, every unclustered node and every size-1 cluster is folded into one pseudo-block labelled __outliers__, so the sampler never has to treat them as a special case. The flag drop_outlier_outlier_edges is off by default, so outlier-outlier edges survive into the pseudo-block's diagonal.

input G · dashed rings enclose each block assignment.csv
caveat: outlier_mode=singleton replicates the outlier subgraph

Switch --outlier-mode to singleton and every outlier becomes its own size-1 block, with its own row and column in \(e\). The urn for that block contains a single node repeated \(k_u\) times, so the sampler has no choice on the outlier side: outlier–outlier edges come back exactly (one stub from each singleton urn lands on the only resident), and outlier–cluster edges keep the outlier's per-cluster degree exact (only the specific cluster-side neighbour is rerolled).

The motivation for this project is benchmarking community detection algorithms, which is a contract: we hand the algorithm a synthetic graph plus a ground-truth clustering and ask whether the algorithm can recover it. Singleton mode breaks that contract whenever the outliers themselves carry community structure that the reference clustering missed. The synthetic preserves that structure verbatim while the ground truth claims those nodes are unclustered. An algorithm that finds the hidden communities looks wrong; one that misses them looks right. Use the default combined mode for benchmarking. Singleton mode is fine when the goal is replication, not benchmarking.

profiling · the edge count matrix

Count edges per block-pair. That is the only structure the sampler sees.

Read \(e_{rs}\) as a stub (half-edge) count: how many half-edges from block \(r\) land in block \(s\). For \(r \neq s\) that is also the number of edges between the two blocks and the matrix is symmetric \(e_{rs} = e_{sr}\). For \(r = s\), each intra-block edge has both of its half-edges inside \(r\), so it contributes twice:

\[ e_{rr} \;=\; 2 \cdot \bigl| \{\, \{u, v\} \in E \,:\, b_u = b_v = r \,\} \bigr|. \]

This half-edge reading is what makes the diagonal doubling natural, and it matches graph-tool's undirected convention. It is not how most SBM write-ups introduce \(e_{rs}\) (they usually call it "edge count" and then note the factor of two as a bookkeeping detail), so expect a small re-orientation if you are coming from there.

The matrix has one row and column per block, so on this synthetic it is a compact 4x4. Each edge contributes to exactly one cell (diagonal) or to the pair \((r, s), (s, r)\) (off-diagonal). Click any edge to highlight the cell it lands in, or click a cell to light up every edge that contributes to its count: the sampler will not remember which specific edges were there, only that the cell owes that many.

why this is the whole contract

Two graphs with the same \(e_{rs}\) matrix and the same degree sequence are equally likely under the degree-corrected SBM. The model cannot tell them apart and the sampler spreads probability across all such graphs uniformly. That is why SBM matches \(e_{rs}\) and \(k_i\) in distribution but reshuffles which specific pairs are connected: the specific pairs are not in the contract.

generation · sample the multigraph

Stub-matching per block-pair, micro-canonical.

Each node \(u\) has a target degree \(k_u\). Build one urn per block: for block \(r\), drop each node \(u\) with \(b_u = r\) into the urn \(k_u\) times. The urn is a bag of half-edges and that is all it is; it does not remember which target block any particular half-edge was supposed to land in. The spokes drawn around each node visualise its share of the urn.

For each block-pair \((r, s)\) with \(r \le s\), iterate in row-major order on the edge count matrix. The pair claims \(e_{rs}\) edges. For \(r = s\) pull two half-edges out of urn \(r\) per edge; for \(r \neq s\) pull one out of urn \(r\) and one out of urn \(s\) per edge. Sampling is uniform without replacement. Every draw becomes an edge; nothing is rejected.

profile records more than the sampler uses

Profile knows the finer split \(k_u^{(s)}\), the count of \(u\)'s edges that fell in block \(s\) on the input (\(\sum_u k_u^{(s)} = e_{rs}\) for \(r \neq s\), \(= e_{rr}\) for \(r = s\)). graph-tool drops the split: only \(k_u\) and \(e_{rs}\) survive into the sampler. So in any one sample, \(u\)'s per-block degree fluctuates around \(k_u^{(s)}\) under the constraint that the column totals stay at \(e_{rs}\). On a hub with a strong block-preference in the input that preference is preserved in expectation only.

graph-tool accepts non-equality input

We feed gt.generate_sbm a \((k, e)\) pair that satisfies the identities above, but the function actually accepts looser input: the consistency condition is only the inequality \(\sum_{u \,:\, b_u = r} k_u \;\ge\; \sum_{s} e_{rs}\) (LHS = stubs available in block \(r\), RHS = edges incident to \(r\)). When the two sides match exactly, the sampler distributes the stubs the natural way. When they do not, some nodes come out with a degree below the requested \(k\): graph-tool prioritises hitting \(e_{rs}\) over hitting \(k_u\). A minimal example: \(b = (1, 1)\), \(k = (3, 3)\), \(e = (4)\), i.e. two nodes both asking for degree 3, with four half-edges on the diagonal. The condition \(3 + 3 \ge 4\) holds, but only as a strict inequality, and the sampler reliably returns one node with degree 1 rather than 3. The identities we use on this page (equality, not inequality) are why the toy runs above behave cleanly.

caveat: counts, not distinct pairs

The constraint is on counts, not distinct pairs. When a hub's stub lands next to one of its own other stubs (same block, \(r = s\)) the sampler emits a self-loop. When two of a hub's stubs for block \(s\) pair with two of another node's stubs for the same block, the sampler emits a parallel edge. Both are legal under the micro constraint. generation · dedup

Collapse parallels, drop self-loops. Degree sequence stops being exact.

Every generator in this project ships a simple graph, so the last step of gen.py is a shared utility, simplify_edges, that drops self-loops and collapses parallels in pandas. graph-tool's own remove_parallel_edges + remove_self_loops would do the same job; we keep the pandas version so the guard is identical across sbm, ec-sbm, abcd, lfr, and npso. Each parallel edge between \((u, v)\) is collapsed to one; each self-loop on \(u\) is dropped. Every dropped half-edge is a unit of degree the sampler can no longer account for, so the output degree sequence sits at-or-below the target.

caveat 1: dedup loss is not uniform

The red heatmap above is the story. Parallels collide where stubs concentrate, so the loss clusters on the diagonal of dense blocks and on the outlier pseudo-block; most off-diagonal cells keep their edges. On dnc, the hardest-hit cell alone loses 894 half-edges (out of 2,450) and the outlier block loses 108 of its 278 intra-edges. The degree sequence "we matched your hubs" is partly true pre-dedup and partly false post-dedup, and the discrepancy tracks block density.

caveat 2: global cc is not a target

The micro constraint pins \(e_{rs}\) and \(k_i\) but nothing about triangles. The stats table captures this: input cc 0.548, output cc 0.341. DC-SBM lands near the input cc when most of the input's triangles were degree-driven; on structured graphs like dnc where triangles sit inside dense communities, the sampler misses by a lot. If triangles matter, ec-sbm-v1 and ec-sbm-v2 add that level of structure on top.
