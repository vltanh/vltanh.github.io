Formal Phylogenetics

Lean 4 formalizations of papers on phylogenetics, each audited against the paper, grown as a tree of repositories, from a shared root library through hubs of inference and of theory to the papers.

Phylogenetics reconstructs evolutionary history from the DNA of living species. Its methods estimate an alignment of the sequences, a tree for each gene, the species tree inside which the gene trees evolve, or a phylogenetic network when species also exchange genes, by hybridization or gene flow. Many of these methods come with theorems: that the model identifies the tree or the network from the distribution of the data, and that the method recovers it as the data grow. The proofs mix combinatorics, probability and algebra, run over many pages and supplements, and are rarely checked line by line.

This project formalizes papers of the field in Lean 4, with Mathlib, and audits each one against its text. The formalization states every result of the paper, proves it by the paper’s own argument wherever that argument works, and a report lists what is false as printed, which hypotheses are missing, which steps have gaps, and how each was repaired.

The structure

The repositories form a tree, and each node holds what the repositories below it share.

  • The root, lean4-phylogenetics, holds the library Phylogenetics that every repository requires: trees and networks, Kingman’s coalescent, the multispecies coalescent and its network version, and concordance factors. It also holds the registry of the repositories, the conventions, the workflow, and the tools that check the collection and write its READMEs.
  • The hubs branch from the root, in two kinds. A hub of inference gathers the methods that estimate one object: alignments, gene trees, species trees or phylogenetic networks. A hub of theory gathers the general results that the methods rest on: combinatorics, algebraic phylogenetics, statistical theory and geometry. Each hub holds a library for what its papers share, and a catalog of the papers to formalize, sorted into families, whose checklist is in the hub’s README.
  • A sub-hub branches from a hub when some of its papers share more with each other than with the rest: the tree of blobs is a sub-hub of networks.
  • The papers are the tips. Each paper has a repository of its own under its hub, with the paper’s library, the audit report, the credits, and the files of an entry of the Palomar registry: a Challenge with the statements, which imports only Mathlib, and the Solution that proves them.

A definition or a result lives at the lowest node above every repository that uses it: in a paper’s repository when only that paper uses it, in a hub’s library when several of its papers do, and in the root when papers of several hubs do. Each repository requires the libraries above it at fixed commits, the same for the whole collection, so every formalization keeps building while the libraries grow.

The catalogue reads the hubs’ catalogs and shows every method, piece of software and theorem in them along time, with the citations between them.

Verification

Lean’s kernel checks every proof, and each repository’s CI checks on every commit that its declarations depend only on Lean’s standard axioms. No result of the literature is assumed. For the finished formalizations, independent AI agents checked the statements against the papers and compared the proofs with the papers’ arguments. No person has reviewed the proofs.

What’s next

The catalogs list the papers still to formalize, from alignment methods to the geometry of tree space. Results that papers of several hubs use move up into the shared libraries.
